## 初步判断
1. 用户反馈 GLM-5.3-flash"写得不太行"与榜单一致：Flash 档在中文内容质量上有差距；但当前提示词本身有冲突和补丁，**先换新提示架构再比较模型**，否则测到的是提示词问题。
2. 量化版本地部署会进一步损失长文风格稳定性（已有 oMLX 版本出现 35.6k 字重复膨胀）。先用全精度 API 测出上限，再测量化版下降多少。
3. 叙述类章节是质量瓶颈，值得用最强可用模型；抽取/结构化/检查可用便宜模型；检查器用与写作模型**不同家族**的模型，减少共同盲点。

## 对比实验（M1 内完成，约半天机时）
- 候选：DeepSeek-V4.1-Flash（API 全精度 + 本地量化）、MiMo-V2.6-Flash（本地量化，可加 API 版）、GLM-5.3（非 Flash，API）、GLM-5.3-Flash（现有）、Kimi-K3 或 Qwen3.8-Max（国产强模型上限参照）、Gemma-4-31B（本地对照）。数据允许出境时可加一个国际顶级闭源模型作上限参照。
- 任务：3 个 dev 项目 × 6 类章节（概要、疾病背景与治疗现状、研究依据/获益风险、总体设计叙述、AE/SAE 惯例条款、统计方法叙述），全部用新分层提示和同一 StyleKit。
- 参数：温度 0.7；思考预算统一上限；记录耗时、token、失败率。
- 评分：templates/eval_rubric.md；LLM 评审用非候选家族模型；用户盲评 20–30 对。
- 决策：叙述类选盲评最高且耗时可接受者；若本地量化与 API 全精度差距 > 1 分（5 分制），叙述类走 API。
