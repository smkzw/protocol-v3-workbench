# 写作引擎：在"弱模型"和"过拟合"之间取平衡

## 核心原则
1. **规则放在边界上，不放在文风里。** 模型负责"写得像"，确定性代码负责"数字和事实对"，检查器负责"发现问题"。
2. **用范例教风格，用结构化事实控内容。** "味儿对"主要靠检索到的同类竞品段落（few-shot），而不是更多"不得……"。
3. **提示词只放通用规则。** 个案教训变成检查器或评测用例，不进提示词。
4. **任何新规则先证明能泛化。** 在 ≥3 个不同治疗领域的项目上不退化才能合入。

## 内容三分类（每个 SectionCard 标注 tier）
| tier | 典型章节 | 产出方式 | 不确定性处理 |
|---|---|---|---|
| D 决定类 | 目的/终点/estimand、总体设计、对照、随机盲法、核心入排、剂量、样本量、期中/多重性、SoA | DecisionCard → StudyDefinition → 渲染器出数字/表格；模型只写解释段 | 一律走决定卡：2–4 选项 + 分析 + 推荐 |
| C 惯例类 | AE/SAE/SUSAR、妊娠、揭盲、伦理知情、数据管理、质量监查、保险、出版 | ClauseBank 共识条款（来自 TopK 竞品，带出处与 ICH E6(R3)/E2A/中国 GCP 锚点）+ 模型按本项目参数改写 | 只标可变参数（联系人、时限若竞品不一致、系统名称） |
| N 叙述类 | 背景、疾病与治疗现状、研究依据、获益风险、设计理由、剂量依据、概要叙述 | 模型写作：StyleKit 范例 + 文献证据 + 项目事实 | 逐断言标依据；缺依据的断言标"AI 不确定"并说明缺什么 |

## 竞品语料 → StyleKit / ClauseBank
1. **检索**：CT.gov（同靶点/同类别/同适应症，Ⅱ/Ⅲ期，有 Protocol/SAP 文件优先）、PubMed/PMC 方案补充材料、期刊发表的设计论文；可选 EU CTR。
2. **下载与解析**：PDF → 结构化段落（已有 OCR/翻译链可用）。英文方案经翻译后用于结构和内容惯例；中文语气优先参考用户已有的中文成型方案（注意评测留一法，见 04_EVAL）。
3. **对齐**：每段映射到 TP-MA-07 v2 语义节点（模型分类 + 标题相似度只作候选，最终按内容判定）。
4. **分类与优先级**：同靶点 > 同分子类型同给药途径 > 同适应症 > 同类适应症；新近、Ⅲ期注册研究、有完整方案文件加分。**同药注册研究不得被自动排除**。
5. **用户确认 TopK**（默认 3–5 个），之后生成：
   - StyleKit：每节 1–3 段范例（截断到 600 字内）、术语表（药物类别术语、终点中文名、量表名）、篇幅分布；
   - ClauseBank：同一惯例条款在 TopK 中的共识写法、差异点（作为可变参数）、出处。
6. StyleKit/ClauseBank 是**数据**，存 runtime，不进代码、不进 git。

## 提示分层与预算
| 层 | 内容 | 预算 |
|---|---|---|
| L0 系统 | 角色、来源纪律、不编造、输出 JSON schema、中文监管文风要求 | ≤800 字，全任务通用 |
| L1 章节卡 | 本节目的、必含要素、结构建议、篇幅范围、tier、风险等级 | ≤400 字/节；**禁止出现任何具体药物、疾病、量表名** |
| L2 项目事实 | 与本节相关的 StudyDefinition 子集 + ProjectProfile | 只放相关字段 |
| L3 风格范例 | StyleKit 1–3 段 + 术语表，明确"只学写法，事实一律以 L2 为准" | ≤1800 字 |
| L4 证据 | IB/文献/摘要中与本节相关的证据片段（带 ID） | 按需 |

lint（CI 必跑）：L0/L1 文本中出现药物名、疾病名、量表名、缺陷编号（P0-xx/NEW-xx/R\d+）、轮次字样即失败；L0+L1 超预算即失败。

## 输出合同（每节）
```json
{"section_id": "...", "text": "...",
 "claims": [{"span": "句子或片段", "support": ["evidence_id|fact_path|style_only"], "confidence": "high|medium|low", "why_unsure": "缺什么"}],
 "decision_requests": [{"fact_path": "...", "options": [...], "analysis": "...", "recommended": 0}],
 "gaps": [{"kind": "source_missing|decision_pending|not_retrieved|mapping_failed", "where": "...", "next": "..."}]}
```
正文与缺口可以并存；有依据的内容必须写出来。

## 逐节生成，不再多章一批
- 每节一次调用（概要等长节可分小节）；同一章节组内按依赖顺序生成，后续节可读取已生成节的摘要以保持一致。
- 温度 0.6–0.8；思考预算对叙述类设上限（风格写作不靠长思考）。

## 检查器（生成后，只标记不偷改）
| 检查器 | 方法 |
|---|---|
| 事实一致 | 正文中的数字、剂量、组别、访视日、终点名与 StudyDefinition 比对（确定性） |
| 风格泄漏 | 正文实体/数字与 StyleKit 范例实体比对，命中竞品药名、剂量、样本量即标记（确定性） |
| 跨章一致 | 目的↔终点↔SoA↔统计、剂量↔组别↔给药、分析集↔estimand（确定性 + 异族模型复核） |
| 过程话术/占位 | 正则清单（只检测） |
| 依据覆盖 | low-confidence claims 比例、无依据断言 |
| 数字复算 | 样本量等只用结构化参数经计算器复算，不解析正文 |
发现问题 → 带具体问题的定点重写（≤2 次）→ 仍失败则保留正文并标记给用户。**禁止用正则替换模型正文中的数字。**

## 风险分级与"选择题"
- 风险 = SectionCard.tier/风险等级 × 本次 confidence × 检查器结果。
- 高风险 + 存在实质选择 → DecisionCard（2–4 选项，每个选项写"适用条件、对样本量/可行性/监管的影响、竞品怎么做"，推荐默认预选）。
- 中风险 → 正文写好，在具体句子上标"AI 不确定：原因"。
- 低风险 → 不打扰。
- 每次生成后给用户的待办 ≤10 条，按风险排序。

## 缺陷处理纪律（反过拟合）
每个质量缺陷必须先回答"哪个通用机制失效了"：范例选错？事实没进 L2？章节卡缺要素？检查器缺失？然后修机制。禁止：按标题/关键词写死医学内容、在提示词里加个案句子、在代码里加适应症分支。
