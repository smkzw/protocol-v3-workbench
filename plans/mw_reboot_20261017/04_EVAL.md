# 评测体系：用成型方案做"留一法"对比

## 目的
用户手里的成型方案不完美，但达到初稿标准。用它们做参照，量化"框架完整、味儿对、关键设计少错、风险提示准"，并防止系统对这几个项目拟合。

## 黄金集
- 每个成型方案建一个 fixture：`eval/fixtures/<project_key>/`（**存 runtime 或私有目录，不进公开 git**）。
- 从成型方案中抽取**开局输入**：药物名、靶点、分子类型、给药途径、适应症、分期（必有）；可选再给 synopsis 作为第二种入口。
- 同时抽取**参照答案**：按语义节点切分的正文；关键设计事实（终点、estimand、样本量参数、剂量、对照、随机盲法、核心入排、SoA 骨架）。
- 划分：dev 集（Agent 可看参照、可调试）和 held-out 集（至少 2 个，Agent 不得查看参照正文，只看汇总分数）。按治疗领域/设计类型分散。
- 另加 2 个无参照的"新领域冒烟项目"（与现有项目都不同的适应症和分子类型），只测覆盖率、一致性、泄漏。

## 防泄漏（必须）
- 评测项目 X 时，X 的成型方案及其各版本**不得**进入竞品语料、StyleKit、ClauseBank、few-shot。
- 公司其他成型方案可以作为中文风格语料，但需记录使用了哪些。
- 设计决定卡的评测只能用开局输入回放，不能把参照答案注入 StudyDefinition。

## 两种回放模式
1. **自动选择模式**：所有决定卡自动采纳 AI 推荐 → 测"推荐质量"。
2. **参照选择模式**：决定卡选择最接近参照的选项（由脚本按参照事实匹配）→ 测"给定正确设计时的写作质量"。两者分开报告。

## 指标
| 指标 | 定义 | 首版门槛（可调） |
|---|---|---|
| 覆盖率 | 适用节点中有实质正文（非提纲、非占位、≥最小篇幅）的比例 | ≥90% |
| 事实冲突 | 正文与 StudyDefinition 矛盾的数量 | 0 |
| 推荐命中 | 关键决定卡：参照选择是推荐项(hit@1) / 在选项中(hit@k) | 报告，不设门槛，跟踪趋势 |
| 关键设计错误 | 参照选择模式下，关键设计在正文中写错的数量 | 0–1/方案 |
| 跨章一致 | 一致性检查器报错数 | 下降趋势 |
| 风格盲评 | 同一节"生成 vs 参照"成对盲评，评分表见 templates/eval_rubric.md；LLM 评审 + 每里程碑用户抽检 20 对 | 生成≥参照的比例 ≥35%（里程碑逐步提高） |
| 泄漏率 | 正文出现竞品药名/剂量/样本量的节比例 | 0 |
| 不确定性校准 | 被标"不确定"的位置中实际有问题的比例（精确率）；实际问题中被标出的比例（召回率） | 报告并跟踪 |
| 打扰量 | 每份方案用户需处理的提示/决定数 | ≤40 |
| 时间/成本 | 全文生成墙钟时间、token | 全文 ≤60 分钟目标 |

## 产出
- `eval/run.py --set dev|heldout|smoke --mode auto|reference` 输出 `eval/reports/<date>_<git_sha>.json` 与一页 `summary.md`（只含分数和前10问题，不含参照全文）。
- 节级 diff 视图（生成 vs 参照并排）供人工查看 dev 集。

## 合入门
- 改动写作引擎/提示/检查器的 PR：dev 集不退化 + held-out 汇总不退化 + smoke 无新增泄漏/冲突。
- 退化时不得修改指标或参照；回到机制分析。

## 人工
- 每个里程碑末，用户盲读 2 份完整初稿（不告知哪份是哪个版本），回答："能否作为初稿交给团队？最需要改的 3 处？"。这是最终判据。
