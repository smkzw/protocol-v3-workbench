## D001 最终产物质量与人工会签边界

**决定：采用原选项 C，并按用户补充要求解释。**

- 产品内不建设医学、统计、法规的强制会签工作流。
- 独立 AI 审阅与确定性 QC 全部通过后，方案状态可直接标记为
  `可提交定稿`；用户随后自行完成人工审阅，人工审阅不作为产品运行的
  强制阻断节点。
- AI 的目标不是“待专家补完的初稿”，而是内容、逻辑、证据、语言、
  结构和 Word 格式均达到可提交定稿水平的完整文件。
- 正文、表格、图、目录、引用、附录和导出物不得出现 `待医学确认`、
  `待统计确认`、`待法规确认`、`TBD`、`TODO`、占位符、模型日志、内部
  prompt/状态机文本或其他未完工痕迹。
- 若关键事实仍未解决，工作流必须在生成最终文件前通过证据推理、AI
  推荐和必要的用户选择完成收敛；不能把未解决项写入最终正文后仍宣称
  `可提交定稿`。
- 该状态表示产品的内容质量与交付完成度目标，不代表监管机构必然接受
  或免除申办方/用户自身的最终责任。

## D002 TP-MA-07 模板权威

**决定：采用选项 A。**

- TP-MA-07 是Ⅱ/Ⅲ期临床试验研究方案的公司权威母版。
- 模板的稳定语义节点、主章节顺序、表格/图形位置逻辑、样式、section、
  域、书签和交叉引用均纳入版本化 Chapter/Word Contract。
- 条件章节可依据显式适用性规则启用或停用；AI 不得自行改名、合并、
  移位或删除权威章节。
- 研究设计确有新增内容时，应映射到既有语义节点；只有既有节点无法
  承载且通过模板扩展规则时，才可增加版本化扩展节点。
- Ⅰ期研究不强行套用 TP-MA-07，后续建立独立的Ⅰ期模板与章节合同，
  但复用同一事实、证据、规则、工作流和 Word 平台内核。

## D003 研究事实的唯一权威

**决定：采用选项 A。**

- `StudyDefinition v3 / PICOS-M-A-Opr` 是研究设计事实的唯一 canonical
  authority。
- 方案摘要、章节正文、SoA、研究流程图、表格、附录和 Word 都是该事实
  图的版本化受控投影，不得分别维护独立事实。
- 用户在摘要、正文或结构化编辑器中修改剂量、终点、样本量、访视等事实
  时，系统必须先形成 typed change proposal，校验来源和影响，再以 CAS
  更新 canonical facts，并重投影全部受影响产物。
- 纯措辞、格式或不改变事实含义的编辑可保留在 semantic block 层；一旦
  触及事实路径，就必须进入事实变更流程。
- 每个投影保留来源 StudyDefinition revision/hash；旧投影失效而不被静默
  覆盖，避免 Synopsis、正文、SoA 和 Word 之间漂移。

## D004 高影响研究设计的用户介入方式

**决定：采用选项 A，并按用户要求细化关键设计总览。**

- AI 先基于竞品试验设计、指南/指导原则、研究药物资料、目标适应症与
  当前 StudyDefinition 完成比较分析，再形成关键设计总览；不能把空白
  问卷交给用户填写。
- 总览可细化为多个设计卡片，至少覆盖人群、剂量/给药、对照、主要目的
  与 endpoint/estimand、研究类型、随机/盲法/分层、样本量/alpha/多重性/
  中期分析、关键安全与停止规则、核心评估/SoA 和运营可行性。
- 每张卡片默认呈现：
  1. AI 最推荐且预选的默认项；
  2. 若干其他可行推荐项；
  3. 每项简短理由、关键依据、相对优劣和主要影响；
  4. `其他，请输入` 自定义入口。
- 用户可以一键接受全部默认推荐，也可以逐卡点选修改；常规路径不要求
  用户逐项输入或打开证据详情。
- 选择 `其他，请输入` 后，AI 负责把自然语言转成结构化候选，检查科学
  性、可操作性和跨域一致性，向用户显示解析结果与影响后再采用。
- 证据冲突、低置信度或重大安全/可行性风险才成为强制阻断；其余默认
  推荐可以批量确认。
- 批量确认绑定设计快照/hash 和幂等键；不能重演为多次采用。任何改选
  都通过 canonical impact graph 失效并重建受影响的 Synopsis、章节、
  SoA、流程图、统计内容和 Word 投影。

## D005 Agent②内部的临床/统计职责

**决定：采用第 1 个选项，即 A。**

- 用户只看到一个“方案设计与摘要 Agent”和一套关键设计总览，不承担
  多 Agent 协调工作。
- Agent②内部至少拆分为临床设计 worker 与统计/estimand worker；两者
  使用隔离上下文、各自的输入合同和专业规则，可并行分析。
- 临床 worker 负责疾病/人群、干预/对照、医学目的/终点含义、安全性、
  评估和运营医学可行性；统计 worker 负责 estimand、样本量、alpha、
  多重性、中期分析、分析集、缺失数据、敏感性与统计方法。
- 两路结果进入确定性 consistency reducer，校验 objective → estimand →
  endpoint → analysis、事件率/效应量 → 样本量、访视/评估 → 分析窗口等
  跨域关系。
- 普通分歧先由系统在有界循环内重新取证和收敛；只有无法安全自动消解
  的分歧才进入用户关键设计总览。

## D006 来源权威、时效与相关性规则

**决定：采用选项 A，并建立比固定来源排序更细的多维权威矩阵。**

### 事实类型与来源角色

- 研究药物事实优先使用当前项目已确认信息、最新版研究者手册及药物自身
  的临床/非临床证据；不能由竞品方案反推成目标药物事实。
- 监管与方法学约束以目标司法辖区当前有效的法规、技术指导原则和正式
  标准为准。
- 疾病诊疗、标准治疗、评价工具等依据优先使用最新且适用的高质量指南、
  共识和量表原始/验证资料。
- 竞品方案、注册信息和论文用于设计比较、参数估计、可行性判断与措辞
  参考；公司历史语料主要服务于结构、模板和中文监管表达。

### 版本与时效

- 对监管文件、指南和共识建立版本 lineage：生效/失效日期、被替代关系、
  司法辖区、适用范围和检索日期。
- 当前有效最新版作为规范性默认；旧版不能与最新版等权，其置信度和权重
  相对降低，并明确标记为历史背景或特殊适用证据。
- “更新”不等于在所有问题上都更适用；若新版范围不同或未覆盖目标人群，
  AI 必须说明适用性差异，不能只按发布日期机械排序。

### 竞品相关性评分

竞品优先级至少综合：

- 时间新旧与当前研究状态；
- 相同靶点/机制、同药物类别及药理可比性；
- 适应症、表型/疾病亚组、严重程度、治疗线次和既往治疗；
- 年龄、地域、基线风险、生物标志物和其他人群相关性；
- 剂型、给药途径、剂量/频次/周期和背景治疗；
- 研究分期、设计类型、对照、随机/盲法/分层；
- objective/endpoint/estimand、评估工具、时间点和统计假设；
- 样本量、中心/国家、招募与运营环境；
- Protocol 完整性、来源真实性、结果可获得性和方法学质量。

与目标研究药物、疾病亚组、人群和严重程度更贴合的竞品，应获得更高的
优先权重；评分分解和主要加/减分原因必须可解释，不输出一个不可审计的
黑箱总分。

### 不确定性与用户裁决

- 普通冲突由 AI 重新检索、比较适用性并在有界循环内收敛。
- 把握不足、关键来源冲突或不同选择会显著改变设计时，系统生成问题列表：
  推荐默认项、其他可选项、各自依据/利弊/不确定性/下游影响，由用户点选
  或通过 `其他，请输入` 补充。
- 未解决冲突不得隐藏在正文中，也不得以 `待确认` 字样进入最终文件。

## D007 Opr 运营可行性范围与国家默认值

**决定：采用选项 A；国家/地域默认按中国国内多中心。**

- Opr 覆盖所有会实质影响方案设计的运营因素，但不建设完整 CTMS、预算、
  人员排班或供应商采购系统。
- 默认研究地域与组织形态为中国国内多中心，系统不把这一默认事实再次
  作为空白问题交给用户。
- 只有目标药物开发策略、适应症人群分布、样本量/招募可行性、监管路径
  或用户资料明确支持其他路线时，AI 才把单中心、国际多中心等作为有依据
  的备选项呈现。
- Opr 至少结构化评估：潜在患者池、中心类型/能力/数量、竞争研究、预期
  入组率、启动/招募/治疗/随访周期、筛选失败率和脱落率、访视负担、侵入
  性操作、样本采集/运输/稳定性、中央实验室/阅片、药物供应、随机/盲态/
  应急揭盲、远程/去中心化操作、关键 vendor/设备/量表依赖及中国地区差异。
- Opr 不是独立说明性附件：其输出必须反向约束入排标准、中心数、样本量
  假设、访视窗口、评估频率、治疗/随访期、操作复杂度和风险缓解措施。
- AI 给出默认中国多中心运营假设及依据；若出现低可行性或证据冲突，进入
  关键设计总览，由用户在推荐方案和备选方案中点选。

## D008 Agent④ 的否决与自动返修权限

**决定：采用选项 A。**

- Agent④使用与 Agent②/③隔离的新上下文，只接收待审 artifact、版本化
  验收规则和必要外部证据，不接收写作者的私有推理记录或共享 memory。
- Agent④负责发现、定位、分类、分级、给出证据和 verdict；其 PASS 是
  `可提交定稿` 的必要条件。
- 每条 finding 至少包含 semantic/block locator、问题类型与严重度、违反
  的事实/章节/Word 合同、证据、影响范围、repair owner 和验收条件。
- 语言、格式、引用、交叉引用、编号及低风险一致性问题可由确定性工具或
  Agent③自动定点修复。
- 医学设计、研究事实和统计问题分别路由回 Agent②临床或统计 worker；
  Agent④不得直接覆盖 canonical StudyDefinition。
- 返修是有界的 owner-routed loop；每次产生新 revision/hash，并由新的
  独立审阅尝试重新验收，不能让原 writer 自己宣布完成。
- 普通缺陷在后台自动收敛；只有达到重试上限、关键证据冲突、重大安全/
  科学不确定性或多个合理方案无法自动取舍时，才形成问题+选项+分析供
  用户确认。
- Agent④不得一边判定一边静默重写，也不得把未解决 finding 隐藏后标记
  `可提交定稿`。

## D009 Chapter Contract 与执行粒度

**决定：采用选项 A。**

- TP-MA-07 的每个叶级 `semantic_node_id` 都建立独立、版本化 Chapter
  Contract，覆盖事实、证据、claim policy、输出 block、跨章依赖、QC、
  repair owner 和 Word object contract。
- 不创建 110 个常驻 Agent。Agent③是一个受控的章节写作角色，按不同
  Chapter Contract 实例化临时 worker。
- 实际执行按 dependency graph 把强相关叶节点组成 writing packet；相互
  独立的 packet 可并行，强依赖节点按拓扑顺序执行并由 reducer 汇合。
- 合同覆盖以 110 个叶节点为验收矩阵，执行批次和并行度则由依赖、模型
  上下文、证据完整度和资源门动态决定，不能再用固定“每8章一批”。

## D010 AI-first 主界面层次

**决定：采用 A + C 组合；B 仅用于最小必要信息引导。**

- 默认单页工作区纵向分为两层：A 型“AI 统筹/例外审核”在上，C 型“文档
  全文工作台”在下；不是两个互相割裂的产品页面。
- 上层只呈现 AI 阶段结论、少量关键选择、推荐默认项、异常、进度和一键
  接受全部；普通后台工作和日志不占用户注意力。
- 下层正文实时按最终交付版本的 Word 样式渲染，包括页面、页眉页脚、
  标题编号、表格、图、引用、目录/交叉引用和分页效果；用户不应在一个
  与最终 Word 外观脱节的纯文本编辑器中工作。
- 上层每个推荐/异常与下层 semantic block 双向锚定：点击推荐可定位到
  正文，点击正文标记可查看 AI 推荐内容、简要分析、来源、备选方案和
  下游影响。
- 正文工作台提供可开关的非导出审阅 overlay，区分 AI 推荐/已采用、需要
  选择、证据摘要和 QC 阻断；高亮/边栏标记不得污染 canonical 文本或
  最终 Word。
- C 层保留选段精确改写、扩写、缩写、润色、结构化事实修改和影响分析，
  但默认不要求用户进入或逐章操作。
- B 型向导只在建项或中途缺少“AI 无法精准检索、抽取或推荐所必需的核心
  信息”时启用；AI 先自动补全，仍无法推断才一次一问、预选推荐，避免
  变成长表单。
- 目标用户明确为资深但懒惰、视觉敏感且不愿学习复杂软件的医学写作人员。

## D011 核心 Word 式编辑器与选区 AI

**决定：A+C 组合结构视觉确认通过；补充核心区必须是完整 Word 式直接
编辑器，而不是只读预览或简化富文本框。**

- 中间核心画布在同一个模型中完成最终样式实时渲染和直接编辑；不能用
  “左边编辑 Markdown/HTML、右边另开预览”的双份内容路径。
- 编辑能力至少覆盖研究方案所需的完整 Microsoft Word 操作面：
  - 样式库与样式继承、字体/字号/颜色/强调；
  - 段落对齐、缩进、行距、段前段后、制表位、项目符号/编号和多级标题；
  - 插入/编辑表格、行列、合并/拆分、宽高、单元格、边框/底纹、对齐、
    重复标题行和跨页行为；
  - 图片/流程图/SoA、题注、公式、脚注/尾注、引用；
  - 页眉页脚、页码、页面尺寸/方向/页边距、分页/分栏/分节；
  - 目录、图表目录、书签、交叉引用和域更新；
  - 查找替换、撤销重做、复制粘贴、格式刷、批注/修订及常用键盘快捷键。
- 工具栏、右键菜单和快捷键按用户熟悉的 Word 心智模型设计；高级功能可
  渐进展开，但不能因“AI-first”而删掉专业人员需要的精修能力。
- 用户选中一句、多句话、一个段落、表格单元格或细分语义章节后，右键
  至少可调用 `AI润色`；同一菜单可扩展改写、扩写、缩写、中文监管语气、
  补证据和一致性检查。
- 选区使用 `block_id + semantic_node_id + range + revision + selected_hash`
  锚定，不能依靠全文字符串唯一匹配。
- AI润色默认保留事实、数字、受保护术语、引用、书签和格式；生成可比较
  候选和局部 diff，用户可采用、再生成或撤销。若改写改变事实语义，必须
  转为 D003 的 canonical fact change proposal 并传播影响。
- AI推荐/分析/QC overlay 与正文内容分层；关闭标记或导出时不残留颜色、
  批注式内部结论、prompt 或工作流痕迹。

## D012 DOCX 导出与 Microsoft Word 修改回流

**决定：采用选项 A。**

- 系统内 canonical semantic document 是权威工作版本；D003 的
  StudyDefinition 仍是研究事实权威。DOCX 是完整、可提交、可继续在
  Microsoft Word 编辑的交付物，而不是不可编辑快照。
- 导出的 DOCX 携带稳定但不污染可见正文的 semantic block、bookmark、
  template/version、document revision/hash 与 lineage 标识，以支持安全
  round-trip。
- 用户在 Word 中修改后可重新导入；原导出文件和回流文件均作为只读
  immutable artifact 保存，不能原地覆盖历史版本。
- 系统生成四类差异：正文措辞、格式/样式、文档结构/Word 对象、研究事实。
  纯措辞和格式可按 semantic block 合并；事实性变化转为 D003 的 typed
  fact proposal，完成来源/一致性/影响检查后再采用并重投影。
- 对无法可靠定位、书签被删除、结构严重改写、域/交叉引用损坏或并发版本
  冲突的修改 fail closed：显示原文、修改后、建议映射和影响，让用户选择，
  不做静默猜测或全文覆盖。
- 合并后创建新 document revision，重新运行章节/跨章/Word QC；通过前不
  覆盖已验证版本，也不能标记为新的 `可提交定稿`。
- 真实 Microsoft Word 的导出→编辑→保存→重开→回流→再次导出是最终
  round-trip 验收门之一。

## D013 B 型建项引导与 Research Seed

**决定：采用 A 的 AI-first 交互方式，但固定核心信息扩展为八类；本决定
覆盖此前“三项最小建项”的旧原则。**

### 核心输入

1. 研究药物；
2. 剂型与给药途径；
3. 预期剂量/剂量范围/队列；
4. 靶点或作用机制；
5. 适应症；
6. 临床分期；
7. 成人、青少年、儿童，可多选；
8. 对照类型或具体对照方案。

中国国内多中心沿用 D007 作为默认值，无需重复输入。用户可上传研究者
手册、Synopsis 或其他资料，AI 应优先从资料中抽取并预填上述字段，让
用户确认而不是重新录入。

### 非标准输入与语义归一化

- 所有字段接受自然语言、简称、商品名/代号、拼写变体、中英文混输和
  不完整表达；不能要求用户先掌握标准术语。
- 保留 `raw_input`，同时生成 canonical value、受控词表/ontology ID、
  synonym match、单位标准化、解析置信度和候选列表。
- 研究药物解析别名/研发代号/通用名；靶点解析基因、蛋白、配体、通路和
  机制同义表达；适应症解析疾病、亚型、表型和严重度；剂量解析数值、
  单位、频次、周期、滴定和多个 cohort；对照解析安慰剂、活性对照、
  标准治疗、背景治疗、无对照及组合方案。
- 成人/青少年/儿童支持多选；具体年龄界值后续按目标司法辖区和方案规则
  投影，不能只把标签当成固定年龄数字。
- 高置信、唯一匹配可自动归一化并显示可撤销结果；存在多个合理解释时，
  才显示“您指的是哪一种”及推荐候选、简要理由；低置信或关键冲突必须
  二次确认。
- AI 可在部分信息下进行初步资料发现，但进入高精度检索、竞品排序和设计
  推荐前，八类 Research Seed 必须达到 confirmed 或明确的结构化范围，
  不能用空值/猜测静默继续。

## D014 `可提交定稿` 的四层验收门与适用性

**决定：采用选项 A；完整性按项目适用章节计算，不机械要求 110 个节点
全部出现在每份方案中。**

### 适用性基线

- TP-MA-07 的 110 个叶级 Chapter Contract 是规则覆盖矩阵，不是每个项目
  必须无条件出现的固定正文清单。
- 系统根据 StudyDefinition、研究分期/设计、人群、干预、评估、安全、
  统计和模板规则，生成版本化 `ApplicabilitySnapshot`；每个节点记录
  applicable/conditional/not-applicable、依据、触发事实、规则版本和 hash。
- 所有判定为适用的章节必须有实质内容、证据可追溯并通过章节/跨章 QC；
  标题、空段、模板说明、通用套话或统一写“无/不适用”均不算实质内容。
- 未解决的 applicability 冲突是 blocker；不能暂时跳过后仍标记定稿。

### 四层强制门

1. **事实与结构一致性**：StudyDefinition、Synopsis、正文、SoA、流程图、
   表格、附录和统计内容使用同一 revision，全部依赖与交叉引用一致。
2. **适用章节完成度**：所有 applicable 节点均有 source-bound 实质产物，
   引用可定位；占位符、`待确认`、TODO、日志、prompt、模型/流程痕迹为 0。
3. **独立 Agent④ QC**：医学、统计、监管、中文表达、证据、跨章、模板和
   结构 finding 全部闭环，clean verdict 才能继续。
4. **Microsoft Word 原生门**：域/目录/引用跳转、书签、分页、表图、页眉
   页脚、样式、保存重开和 PDF/page 对照均通过真实 Word 验收。

四层全部通过后才可自动标记 `可提交定稿`；任何一层失败都必须返回明确
owner 自动定点修复，不能把 Word 问题留给用户导出后自行处理。

## D015 非适用章节的最终呈现

**决定：采用选项 A。**

- `ApplicabilitySnapshot` 判定为 not-applicable 的条件性节点，不进入最终
  正文和目录；编号、PAGEREF、书签及交叉引用按模板规则确定性重建。
- 适用性规则、触发事实、AI分析和排除理由只保留在系统审计/影响层，
  不作为内部过程说明泄漏到提交文件。
- TP-MA-07 明确要求必须保留的节点，即使某些常规内容不适用，也应生成
  针对本研究事实的简洁、科学、可操作说明；不得只写 `无`、`不适用` 或
  复制通用模板解释。
- AI 不得在每次起草时自由决定删留；最终呈现由版本化模板规则和项目
  ApplicabilitySnapshot 确定。

## D016 目标编排路线

**决定：批准路线 A，进入完整设计分节确认。**

- 应用自有 canonical fact/document graph、Chapter Contract、domain event
  log 和 artifact store；这些构成产品权威控制面。
- 采用开源 LangGraph 作为首选 workflow orchestration kernel，只负责
  checkpoint、interrupt/resume、subgraph、fan-out/fan-in、有界重试和
  路由，不拥有或直接写入 canonical clinical truth。
- 现有 typed state-machine/durable-job facade 和 Microsoft Agent Framework
  保留为 PoC 对照；只有 LangGraph 通过 crash/replay、重复恢复、并发编辑、
  graph/schema migration、审计重放和 fresh-reviewer isolation 后才锁定。
- 不依赖 LangSmith/Agent Server 等闭源控制面；checkpoint store 与产品
  审计账本分离。
- 迁移采用 strangler/adapter，不大爆炸重写既有 provenance、CAS、OCR/
  翻译、Word exporter 和已验证窄合同。

## D017 文档类型范围最终收束

**决定：当前完整多 Agent 协作控制图只用于 Protocol。**

- Agent①–⑤、LangGraph子图、Chapter Contract、章节锁、Agent④ QC、A+C
  工作区和四层定稿门均是 Protocol workflow 的设计，不扩展到 CSR。
- CSR 未来另行完成需求访谈、来源/数值真相层、章节合同、Agent职责、图
  定义和验收；不得把 Protocol graph 改名或简单加分支后称为 CSR workflow。
- 独立 Synopsis 不建立单独多 Agent workflow，也不维护独立事实或章节
  状态。Protocol 全量工作流完成并达到可提交定稿后，提供单独 Synopsis
  导出窗口。
- Synopsis 由最终 frozen StudyDefinition、Decision Graph和相关Protocol
  semantic blocks确定性投影，按独立模板导出DOCX/PDF；若Protocol事实或
  相关章节变化，旧Synopsis导出失效并在Protocol重新通过后再生成。
- 未来可能共享平台级事实、证据、事件、artifact、模型/Harness和Word
  基础设施，但不同文档类型必须拥有独立工作流定义、合同和验收，不能
  共享运行实例或临床状态。
