# 需求修订：双入口、自由工作稿、显式核对

## A. 已由用户明确的决定

### R1 禁止案例拟合

此前 Agent 为跑通某个验证案例加入的病例／研究特定补丁，不是通用产品规则，必须退出通用生产路径。修复不能只替换病例名称、把常量移动到另一个 JSON 文件，或添加“若为另一个疾病则换另一组常量”的特判。

允许的内容来源：当前用户输入、当前项目来源、显式绑定并获适用性验证的规则与配置，以及有依据且保持候选身份的 AI 建议。来源中的原文证据和模型建议必须有不同状态；模型自报置信度不等于已确认事实。

### R2 带缺口的完整工作稿

关键研究设计确认后，非关键组织或运营信息缺失不阻止生成完整结构、可编辑、缺口明确的工作稿。

“完整结构”不等于把缺少内容的章节全删掉，也不等于只生成标题。已有事实支持的内容应真正写出；未知内容用可定位、可持续处理的缺口对象表达。未知不自动等于不适用。

本决定不允许伪造剂量、终点、疗程、来源或审批，也不意味着所有关键设计未定时直接声称完成全稿。关键集按研究类型和实际依赖确定，不新增一个对所有研究通用的巨型必填表。

### R3 自由工作稿＋显式核对

正文、摘要、流程表、表格、标题、脚注、格式等工作稿对象允许用户直接编辑；语义不确定或涉及研究事实不应导致用户输入无法持久化。

工作稿保存、研究设计确认、文档一致性核对、最终交付验收是不同动作。保存工作稿不自动更新已确认的 StudyDefinition。

格式合法、目标存在、项目与版本正确等技术检查仍需保留。自由编辑不是忽略版本冲突、文档损坏或跨项目写入。

### R4 摘要和流程表的编辑所有权

初次生成或内容推荐由 AI 根据当前输入、已确认关键设计及已选资料完成。生成后，摘要和流程表是用户可以直接编辑、增删的原生文档对象；支持自然语言要求 AI 重生成或局部 surgical 修订。

保留确定性表格布局、单位格式、公式／数值核对和文档序列化能力；禁止用它们替代 AI 的设计推荐，或在导出时重新生成内容覆盖人工编辑。

### R5 两种写作入口

入口 A：已有研究方案摘要 → AI 提取相应信息 → 自动预填研究设计 → 用户核对关键项和真正冲突 → AI 撰写全文。

入口 B：从零开始 → 用户逐步输入研究意图 → AI 推荐研究设计选项 → 用户选择／修改 → 同一研究设计 → AI 撰写全文。

“逐步填写”不意味着每一项都由用户从头打字；系统应复用已输入、已提取、已选择的内容，不要求重复抄录。

## B. 两条入口汇合后的共同系统

```text
已有摘要 ─ AI提取/预填 ─┐
                       ├─ 统一研究设计与关键确认 ─ AI完整工作稿 ─ Office自由编辑
从零设计 ─ AI推荐/选择 ─┘                                      │
                                                     显式核对/局部AI修订
                                                              │
                                                    保存版本/导出该版本
```

两条入口可分别有输入界面和准备步骤；共享研究事实、来源身份、决策、稿件、版本、任务恢复和 Office 集成，不建设两套相互转换的事实主库。

来源摘要是带原文 hash、版本和定位的材料；生成稿中的摘要是可编辑文档对象。修改后者不会改写前者；同一个“摘要”名称不能让这两类对象共享可变存储。

## C. 上一轮第五个问题的澄清

“已有摘要输入”是写作起点。它不等于“完整方案导出到桌面 Word，经外部修订后再回传并继续编辑”的循环。

已确认：摘要输入、零起点输入、工作台内原生编辑、DOCX 导出。

未确认：外部 Word 全文改稿回导是否为首版强制验收；EndNote／Zotero 哪个为首个动态引文互操作目标。两者不妨碍双入口和稿件编辑主链实施，不能擅自补成用户承诺。

文献插入、引用身份、编号和文献表维护仍是既有业务要求，不能以“工具未选”将首版偷换成静态文字参考文献。导入已有域时不静默破坏；保留域与第三方插件动态刷新兼容是不同能力。

## D. 对旧规则的明确替代

| 旧规则/假设 | 新规则 |
|---|---|
| 所有适用章节事实齐全才起草 | 关键设计确认即可起草，非关键缺口显式保留 |
| 事实变化不准写入正文 | 可保存工作稿；研究事实更新经显式核对 |
| 摘要/SOA每次导出重新投影 | 初次生成与后续显式更新；导出不改业务内容 |
| 草稿也一律零占位 | 禁止无意义模板占位；允许有身份、位置和处理方式的真实缺口 |
| 修订几个全局疾病常量即可泛化 | 移除案例特判，测试通用输入与来源驱动 |
| 选 EndNote/Zotero 后才能推进 | 主链继续；专项互操作目标单列未决 |

## E. 工程建议：四类状态不得混淆

- 输入候选：从用户、来源或模型得到的设计候选，尚未完成相应确认。
- 已确认设计：StudyDefinition 中按项目确认的事实。
- 当前工作稿：用户正在编辑、已可靠持久化的 DOCX 工作版本。
- 核对/交付状态：该具体文档版本与哪一份设计一致，哪些差异和缺口未处理。

初次引用来源的推荐预填不是自动确认；已确认关键内容不因另一个入口进入而重复确认。

正式导出／发布策略与缺口分级的详细名单为工程建议，需要结合项目当前合同完善；不能把每次保存/下载都变成强制全稿审核。
