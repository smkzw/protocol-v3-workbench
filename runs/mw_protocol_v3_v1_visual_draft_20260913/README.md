# 四步工作台交互设计样稿

workbench.html为离线单文件设计样稿，演示准备资料、八类建议确认、阅读修改、导出状态。不是已挂载v3前端，不含真实研究资料，不生成Word。所有演示研究文字不得用于申报。采用当前设计v1.4及康哲交互轨的品牌/可读规范；用户安静阅读偏好优先，未添加常驻动效。

静态语法、唯一ID、label引用和无外部资源检查通过，见verification.json。浏览器file://导航被URL策略拒绝，未尝试其他浏览器或绕过；没有截图、computed style、溢出或真实操作验收，不得标视觉通过。后续正式V1.4在获准的产品测试入口重新进行实际浏览器验证，不能把该样稿代替产品功能。

实现转接重点：推荐卡来自真实数据，确认应用绑定当前研究版本；正文完整采用/保存走既有SQLite；出处抽屉解析真实来源；导出检查绑定实际Word制品。界面只呈现影响与下一步，不暴露JSON/哈希/队列；缺失参数以最少问题解决。

## V1产品接线的具体用户验收脚本（待真实浏览器执行）

标准资料充分、八类决策均适用的预算：新建1、选资料1、原生打开1；资料低风险事实合并确认1；八卡各一次8；生成全文1；导出1、原生保存1，共15个设计目标动作。不能把选文件后的打开按钮、二次弹窗或预览确认隐藏在计数之外；20为总上限，5次为余量，实际事件记录才是结果。原生对话框采用一份已准备材料集，不要求用户先完成未计数的额外整理流程。

- 推荐预选未确认：进入卡片后既显示理由/来源又可改；一次“确认并继续”记录当前版本，最后一卡完成后进入整稿生成主动作，无重复总确认。无期中/优效路径按已确认事实解释不适用，不产生假确认记录。
- 合法变更：已确认方案修改期中安排→预览不再使用的参数/受影响正文→一次确认；其余无关卡保持。主动恢复期中时旧参数仅作为建议展示，需要适用高风险确认。
- 输入法与保存：中文组合未结束时不能提交半个拼音；显示本机暂存/正在保存/已保存的真实状态，失败保留编辑内容。A章→B章→A章、A项目→B项目→A项目以及刷新验证无串稿；所有待提交动作绑定实际当前页面实例。
- 长任务：超时/失联后保留同操作定位，页面给恢复进展/查看已有稿件；对账前不提供会重复调用的“重新生成”。成功传输但正文解析失败显示已有内容保存范围，不能变成空白成功页。
- 编辑对象：段落A→表1→段落B→表2，修改单元格后保存重开和Word仍保持位置、表格身份、来源与事实关系。预览采用前后变化，取消不改正文。
- 导出：用户点击导出后正常检查自动继续，只有具体未决科学问题返回对应卡/正文位置；通过后提供该次Word保存并验证的制品。渲染检查包括正文/页眉页脚/表头与横向SOA，不能用文件下载成功代替。

以上是测试脚本和设计预算，尚无实际点击/IME/保存/Word通过证据。现有离线样稿不承担这些产品行为，浏览器file://策略拒绝仍如实保留。

### 推荐风险分层的接线补充（待V1实施落实）

继承v2将“常规访视窗”列入low的描述，只适用于已确认科学安排下的展示与格式整理。主要终点评估时间、PK取样及关键安全随访窗口的新增/改变，应归入对应终点、剂量/暴露、核心人群/安全安排的实际设计确认与影响预览，不凭公司惯例自动采用，也不另加一个通用审批平台或每个时间点一张卡。此解释落实当前design第21行“公司旧方案不能覆盖本项目确认事实、有效IB、适用指南及正式沟通”。八类卡的理由可包括其关键时间安排，点击预算不通过隐藏科学决策达标。当前独立review的Plan/design冻结件不在审阅中改写；后续V1任务按此说明核对并在适用阶段归入正式设计。
