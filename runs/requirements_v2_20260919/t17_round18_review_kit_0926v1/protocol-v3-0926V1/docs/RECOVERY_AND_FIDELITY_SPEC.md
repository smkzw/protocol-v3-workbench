# 0926V1 恢复与证据规格（建议，非现有实现声明）

本规格用于扩展现有模型/DTO/服务，不要求新增独立平台或平行状态库。字段可映射到现有对象，重要的是语义与不变量。

## 1. 三种身份必须分开

**研究处理范围**：project、search snapshot、confirmation ID/revision、study facts hash、shortlist ID/revision、selected study IDs、selected protocol IDs/versions、preparation batch ID/scope hash。

**逻辑恢复命令**：recovery command ID、parent command/job ID、reason/change evidence、frozen scope identity、eligible root task IDs、attempt/cost ceiling、no-progress rule、created actor/time。网络重传复用同一命令；用户/受控策略决定的新恢复另建有关系的命令，不等于清空累计预算。

**实际候选评估**：item/span/batch、document/plan/extraction identity、integration ID、candidate hash、expected and observed unit/chunk coverage、source hash、checker version/hash、assessment ID/time、outcome及理由。不能用chapter前缀或latest代替候选身份。

## 2. 范围不变量

- 一个新任务只消费一次明确确认的冻结范围。运行中不能静默换latest prep/最新journey。
- 历史任务恢复原冻结范围，除非明确建立新范围版本并标出替代关系。
- 相关研究不等于本轮深读研究。选择预算计不同研究，不计文件版本/翻译片段。
- 同一研究多个完整方案版本须有选择理由；仅下载/处理入选文件，保留历史缓存身份。
- 缺失字段不是无限降级授权。None合法与有权处理分开验证。

## 3. 写入不变量

所有权威工作状态持久化前，使用字典级完整合同校验。不以model_copy或model_dump成功替代验证。状态耦合（例如retry generation/parent/source、ready状态/候选产物/评估、running/owner）须在统一边界约束。

工作投影可以按有版本、有范围、带审计和CAS的迁移修复；不可变历史不能覆盖。修复前后的payload摘要、目标范围、原因、迁移版本及审计事件可查。无法解析的记录应进入明确恢复路径，不永久堵住所有读取。

合法无父恢复应是一个明确的恢复模式，拥有可核验的恢复记录。synthetic_recovery_只能作为历史兼容标识，不是授权和来源证明。

## 4. 候选及评估不变量

- 评估对象必须是实际拟展示/采用的最终候选，而不是中间Hy文本。
- 完整性从预期范围与实际范围比较得到，不能因为integration列出的几个chunk都存在就认定完整。
- 一份候选可能有多个按版本追加的评估；保留旧评估。新评价不能悄悄更换候选。
- 无完整来源时是NOT_EVALUABLE/DATA_MISSING，不是REJECTED，也不是通过。
- 通过确定性忠实度不等于医学批准、充分参考价值或正式方案可交付。
- 对齐输出、原始输出、source units和失败位置应在失败发生时留存；不要在去掉marker、截断后才保存唯一证据。
- 原始诊断输出不能直接作为完整候选。其恢复要证明覆盖和身份，而非按相似度补配。

## 5. 数值规范化的最低正确性要求

以Decimal等精确数值表示与明确单位/数量级比较，而非删除小数点或匹配数字形状。识别作用域内的数值出现次数、否定/比较关系、区间与单位。能证明的跨单位等价允许通过；未知解析应显式回退为待核验，不以模糊宽恕静默通过。

例：116 million与1.16亿可统一为116000000；1.16万为11600，不能通过。5 mg与50 mg不同。1.5与15不同。两个相同数值在不同语义位置需要分别对应。

本规格只规定安全性与可检验行为，不要求一次性建成完整自然语言数值理解平台；先移除危险通配放宽，再覆盖本轮反例和已证实正确转换。

## 6. 失败分类与调度

| 类别 | 示例 | 行为 |
|---|---|---|
| 共享前置阻断 | 项目/旅程缺失，scope无效 | fan-out前一次阻断，不逐项烧预算 |
| 非法工作状态 | payload耦合字段不一致 | 窄范围迁移/校验，不发送模型请求 |
| 来源/覆盖缺失 | 缺确切integration或units | 无法复检，允许有范围的修复/再生成 |
| 确定性内容错误 | 数字、否定、错配 | 记录对齐错误，有限纠偏，不无限重试 |
| 已知瞬时故障 | 明确未受理的网络/繁忙 | 有界退避并计累计预算 |
| 受理结果未知 | 请求已可能被处理 | 查原任务/持久结果，先对账 |
| 科学未决 | 证据不足而无法给出设计判断 | 推送医学作者少量明确问题，不伪装技术失败 |

上表是建议分类，需映射已有错误合同。对同一错误指纹连续无新增有效结果，进入NO_PROGRESS停止状态。后续恢复须说明发生了什么改变（代码、输入、配置、provider状态），不能只说“换个key再来”。

## 7. 单文档canary

使用已授权、当前入选范围内一份真实Protocol，不另建硬编码专案。选有代表性的数字、否定、表格或访视段落；验证原文身份、翻译实际候选、完整对齐、评估和分析来源，直到可编辑工作稿保存。

canary通过后扩量仍受shortlist、预算和并发边界，不因此放开所有旧队列。跨项目、旧snapshot、多版本和错误场景仍靠正负集成测试覆盖，避免单例拟合。

## 8. 产品内文档的验证边界

保存与科学确认分离。内嵌当前文档保存必须有服务端确认和版本/hash；再次打开/下载对应当前版本，不靠旧导出件冒充。布局变化不能卸载/重新初始化编辑器造成修改丢失。

外部Word下载件在桌面编辑的测试可以单列复用；本轮不默认新增外部文档回传导入能力。任何产品边界变化须明确提出，不用HANDOFF单方面重定义既定目标。
