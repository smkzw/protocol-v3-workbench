## 3. 缺陷与问题清单（P0 / P1 / P2）

### P0 阻断性缺陷（Blocker）
- **缺陷标题**：医学写作工作区前后端构建版本校验不一致导致写作业态全面死锁（P0 门禁阻断）
- **影响范围**：新建项目（`T3-FXIa-02`）与既有历史项目（`T3-FXIa-01`）进入“医学写作”时均百分之百复现，用户完全无法进入方案设计逐问、PICOS、初稿生成及导出流程。
- **复现步骤**：
  1. 浏览器访问 `http://127.0.0.1:5186/`；
  2. 点击“新建项目” -> 勾选“从零开始”；
  3. 输入药物 `T3-FXIa-02`、适应症 `非瓣膜性房颤卒中预防`、分期 `III期`；
  4. 点击“创建并进入写作”；
  5. 页面自动跳转至医学写作模块，立刻渲染红盾警示卡片：“当前版本组合不可进入写作工作区（后端构建与当前前端构建不一致）”；
  6. 点击界面提供的“重新检查”重试按钮，重试请求 `/api/runtime-readiness` 返回当前后端版本 `api-cf279bffff202629`，与前端预期的 `api-a91f7ece9407c5cc` 持续不匹配，页面维持阻断。
- **佐证截图**：
  - `screenshots/04_after_create_submit.png`（提交建项后即刻阻断）
  - `screenshots/05_recheck_result.png`（点击“重新检查”触发重查）
  - `screenshots/06_after_recheck_wait.png`（重查完成后阻断依旧）
  - `screenshots/08_reenter_writing.png`（项目下拉重选后进入依然阻断）

### P1 体验与专业度缺陷
- **缺陷标题**：系统级内部 Git Commit / Build Hash 裸露呈现给临床医学用户
- **问题现象**：在医学写作门禁页面中，面向临床医学经理或统计师的界面直接列出 `web-d6f3b475f8fa7308`、`api-a91f7ece9407c5cc`、`api-cf279bffff202629` 等内部技术构件散列值，没有提供具有临床业务意义的指引（如“系统后台维护中，请联系运维升级服务包至 2026-07-17 版本”）。
- **佐证截图**：`screenshots/06_after_recheck_wait.png`

### P2 功能与交互细节缺陷
- **缺陷标题**：页面刷新后当前选中的项目上下文意外丢失并重置为列表首项
- **问题现象**：当用户在 `T3-FXIa-02` 项目下按 F5 刷新页面后，顶部导航栏的项目下拉框未记忆当前会话操作的项目，而是自动回退为下拉菜单中的第一项（如 `T1-SGLT2口服抑制剂`），导致用户必须手动重新寻找并选择自己的项目，容易导致跨项目误操作。
