# 样本量修订路径规格（P1-53，第11轮末归档，不实现交下一周期）

定位：P0-18 销案（18ed698b）的正确限定——闭环仅覆盖『新输入的 z 向量绑定』
（完成第二步时校验当时参数组合），未覆盖『假设修订后基数不重算』路径。
现场（r11 聚合侧 python 复算独立验证）：AD 项目结构化输入保存
『单侧把握度90%+850例（567/283）』的陈旧推导，声明段却按双侧混写；
38vs18 实际需对照约79例/共约236例，850 在 2:1 下把握度≈100%，
850 反推对应 Δ≈0.10（28%vs18% 时代的基数）——参数修订后复算门未强制
重跑，陈旧基数一路走到导出件。

## 三件实现规格

1. **口径指纹**：sample_size_strategy 结构化解析成功后生成
   `sample_size_fingerprint = sha256(单双侧 | α | 把握度 | δ | SD)[:16]`，
   随 PICOS 提交持久化（contracts 增可选字段）。
2. **强制重算**：PICOS 保存/提交时若解析出的参数重算出指纹与库内指纹
   不一致（假设被修订）→ 复算门强制重跑（既有
   sample_size_declaration_check），新旧推导都留痕
   （old_fingerprint/new_fingerprint/重算结果入 journey 事件，
   供审阅侧看到『基数因何变化』）；不一致且未重算 → 422
   （与 18ed698b 同一人话文案族）。
3. **禁止单双混写**：生成层与导出层校验声明段与推导段的口径词——
   同一章节内『单侧』『双侧』不得混指同一 α/把握度组合
   （AD 现场：输入写单侧、正文写双侧，两套 z 值差22%例数）；
   违反计入导出缺口门（草案-N，与样本量门同机制）。

## 验收（反例先红）

- 修订假设（18%→28%）保存后：不重算即完成第二步被 422 拦截，
  重算通过后新旧指纹与推导均留痕；
- 声明『双侧』而推导按『单侧』的文本在生成层被标记、在导出层计缺口；
- ID701（96/113/230）与 BE204（75/0.8=94/188）正例不误伤。

## 与 18ed698b 的边界声明

18ed698b 输入层门只在『完成第二步』这一时点校验当时参数；本规格补的
是『参数事后修订』路径与口径一致性——两件合起来才是样本量全闭环。
下一周期请勿凭 18ed698b 的存在认定样本量已全闭环。
