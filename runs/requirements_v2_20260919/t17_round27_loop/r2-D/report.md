## 撰写者四问

### M1 人工负担量

今天真正走到的、要我亲手点的：

| 动作 | 次数 | 性质 |
|---|---|---|
| 「新建项目」 | 约 5 | 开对话框 |
| 选「导入方案摘要」 | 约 4 | 入口选择 |
| 选/挂上摘要文件 | 4 | 上传 |
| 「导入并提取」 | 3 | 放行解析 |
| 「继续处理」（解析失败/超时后） | 1 | 例外放行 |
| 「从零开始」（绕过） | 1 | 换入口 |
| 「创建并进入写作」 | 3 | 建项提交，全失败 |
| 「取消」关对话框 | 1 | — |

合计大约 **20 下**，项目还没建出来。

没看到的东西：译文确认、事实逐条确认、缺口勾选、章节冻结、**「高置信自动放行」**、**「批量全选确认」**。不是这些做得不好，是**根本没进到那些屏**。

账：按今天这个点法，正式运作时一个方案从摘要到初稿——光「把摘要吃进去」就要反复点、反复等、等完还可能要你对着英文报错点「继续处理」。后面如果真有逐条确认，负担只会更重。以撰写老师的耐心，这个量级**受不了**。不是「点得勤一点就行」，是入口自己先卡死。

### M2 入口B 解析时长

- 第一次点「导入并提取」：**2026-10-04 23:56:43**。
- 界面有进度：`AI正在提取研究框架与PICOS`、`正在处理 1/1 个内容块`、`已运行 N 分钟`、`模型正被2～3个任务占用`。**不是毫无提示**。
- **约 14 分 44 秒**后出结果，但不是提取表，是红条英文：`chunk 0 validation failed: protocol synopsis non-default value requires source evidence at framing.version`。药物、适应症、分期、设计**一个都没抽出来给人核对**。
- 中途对话框会自己关掉，人还以为失败了；再开「新建项目 → 导入方案摘要」会写「已恢复上次的提取任务」。进度丢了，任务其实还在跑。
- 点「继续处理」开第2次：墙上时钟一直累计到 **36～42 分钟**，最后红条：`解析未完成：模型本次响应超时……繁忙，不是故障`。第2次从点「继续处理」到超时大约 **31 分钟**。
- 抽得对不对：**无法评价**，因为没有提取结果页。

结论：比「干等 32 分钟」好的地方是有排队/已运行分钟数；不好的地方是等完交付的是英文校验/超时，不是能确认的建项信息。

## 逐环节感受

- **易用性**：入口名字清楚——「导入方案摘要 / 导入并提取」，撰写老师找得到。找到之后，进度会丢、报错是英文和 JSON、从零开始也建不成。像一台打印机，进纸口写得很大，纸塞进去就咬住。
- **逻辑性**：口口声声「先解析、您确认后才创建正式项目」，实际确认屏没出现；失败后让你「继续处理」，再失败就说「繁忙不是故障」。撰写老师无法判断是我的摘要不合格，还是系统自己忙死了。
- **美观性**：总看板、对话框、橙白分区比「一堆表单」好看，深度对齐后的壳子能看。表格设计器里却把 `mwcell_greenfield_…` 这种内部编号摊在「属性」里；顶栏 AI 设置直接写 `mtplx-flash-next-optimized-speed`。壳子漂亮，露出线头。
