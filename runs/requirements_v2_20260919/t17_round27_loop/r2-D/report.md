## 4. 逐环节感受

**打开系统**  
页面干净，康哲标识清楚，左边一列模块，右边「+ 新建项目」是橙色，一眼能找到。没有人拦我登录，也没问我是谁。医学写作等模块在没选项目时是灰的，说得通。看板空着写「请选择项目」，34 个旧项目我一个都没点。

易用性：进门顺。逻辑性：没选项目先不让进写作，合理。美观性：浅底、橙按钮，正式产品的样子。

**建项 / 入口B**  
「从零开始」和「导入方案摘要」并排，导入这条的说明写得很明白：先解析、你确认后才创建。选文件像普通网盘上传，不别扭。导入后那三个基本信息框消失，项目名叫什么只能指望解析结果或文件名，撰写的人如果想先把 R2D- 写进项目名，这会儿没地方写。

易用性：入口好找，选文件顺。逻辑性：确认后再建项这个顺序对。美观性：弹窗居中、分区清楚。

**解析等待**  
这是今天唯一真正走深的环节，也是整条链断掉的地方。系统不是没说话：有「AI正在提取」、有块数、有已运行分钟、有第几次尝试、有「模型正被占用/排队」。撰写的人能看懂「在等模型」。等不及的时候它又甩出一长串英文：`chunk 0`、`ensure(triage)`、`mtplx`、`arbitration`、`budget capped`。这不像给医学撰写看的话，像后台日志直接贴到红条上。「继续处理」第一次能把流程拉回排队，第二次（续跑后）点了没反应。卡点到了还在排队，只剩「取消」。

易用性：进度有，但 30 分钟交不出提取结果，写方案的人等不起。逻辑性：失败后让你继续处理，方向对；英文内部词和「继续处理有时没动静」把逻辑打断了。美观性：红条+排队条排版还整齐，内容不像给人看的。

**框架 / 竞品 / PICOS / 初稿 / 改稿 / 导出**  
没走到。不是这些页不好用，是前面的门没开。
