## 五、三张清单

### 清单一：成型方案明显更优之处（系统应学）

1. **法规语言直接落地到条款级数字**：SUSAR 7天/8天随访/15天/第0天/报告起止时间、研究者24小时+匿名化（鉴认代码而非姓名身份证住址——2020版GCP条文式表述）、死亡事件双报+尸检资料——系统的"按ICH E2A及国家相关法规时限"是占位话，应学成型方案直接写时限与口径。
2. **RSI专节**：预期性评估依据（研究者手册/参考安全信息）成节，SUSAR判定的锚点文件明确——系统完全没有这个概念。
3. **安全性沟通联系表**：申办者药物警戒的传真/邮箱/电话成表（6.7.3.4.4，p67）——系统14.3安全信息报告途径空节，骨架里连占位邮箱都退化为"待填写"，应做成结构化联系表字段。
4. **前置件齐套**：CRO签字页、主要联系信息页（五方：PI/申办者/CRO/统计单位/生物样本检测单位）、表格列表、九个量表附录——中国多中心研究的交付习惯件，系统模板未含。
5. **每页版本管控**：RUX每页页眉"机密专用文件 版本号及日期：1.3 2024年08月14日"+页脚"第X页共95页"——文件任何一页被截取都能追溯到版本；系统页眉有编号+DRAFT水印但无版本日期，应补齐。

### 清单二：系统产出更优或更合理之处（成型方案可改进）

1. **草案管控的显式禁止语**：系统页眉"不可用于提交"是成型方案没有的硬管控语（RUX以"机密专用文件"代替，语义弱）——成型方案可在草稿版采用同款显式禁令。
2. **估计目标与主分析方法绑定陈述**：HA501把治疗策略估计目标、救援治疗处理、观察期归一化与负二项模型写进同一段（9.2/4.2），比RUX 8.2的"假设/估计"更可执行。
3. **多重性控制独立成节（9.7）**：HA501/NC401有独立节名承载，RUX的8.3多重性校正亦有——打平；但系统把它放进编号骨架使机读可查，值得保留。
4. **结构骨架统一且机读友好**：三件导出编号章节名集合除一处外完全一致——比手写方案更利于跨项目QA比对（本轮实测的结构一致性是系统优势）。
5. **导出确定性**：写手件与后端链路件字节级一致（本周期md5实测）——成型方案的PDF/docx归档流程无此可复验性承诺（属产品能力而非成型方案缺陷，作为系统侧可保留的优点记录）。
