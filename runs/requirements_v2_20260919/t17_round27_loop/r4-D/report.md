## 撰写人专项探针结果

### S-1 追问专业度

- **做了什么**：在「补充产品事实（自然语言）」里贴了完整设定（硬骨抑素单抗、210 mg 每月皮下、三臂对照、BMD/骨折终点、低钙和心血管监测），点「提交并拆解」，等了约 10 分钟。
- **看到什么**：先是「解析中」+「研究者手册状态保存失败：stale authoring journey revision: expected 3, current 4」；后来变成「事实采集未完成：fact intake AI provider failed: Managed local model server unavailable: ensure(triage) failed on mtplx; queued dispatch aborted」。页面始终写着「尚未发起事实采集」。没有出现「请确认以下 3 个问题」一类真正追问。
- **结论**：两阶段反问这条撰写人最需要的路，今天没走通。系统宣传「每轮最多追问 3 个影响下游设计的问题」，实际零问。
- **问得好（本应出现、我作为撰写人也会问的）**：对照为什么同时要安慰剂和阿仑膦酸钠；骨折史/椎体骨折是否进入联合主要终点。这些我是自己在 PICOS 里补的，系统没问。
- **问得差**：没问到任何问题。高影响缺口一直显示「药物技术类型、给药途径、靶点/作用机制」，而药名里已经写了「皮下注射硬骨抑素单抗」——这更像没读药名，不像懂骨代谢的人在问。
- **截图**：`screenshots/07-事实采集-解析中-IB版本冲突.png`，`screenshots/08-事实采集-解析结束.png`

### S-2 框架医学自洽

- **做了什么**：AI 推荐包只有一句「design模块待AI基于语料生成 / 无置信」，「一键采用」是灰的。我在「总体设计 / 研究目的 / 竞品范围」里手填：随机双盲、安慰剂+阿仑膦酸钠、平行多中心、12+12 个月、确证性+OLE。
- **看到什么**：框架层没有系统生成的互相打架设计（因为它几乎没生成）。我填的三臂对照和「对照类型」下拉只能单选「安慰剂」或「阳性」——没有「安慰剂+阳性」这一档，我只好选「其他（需说明）」再在补充里写三臂双模拟。这是表单能力缺口，容易把 III 期骨药常见的三臂设计写歪。
- **结论**：手填可以自洽；系统推荐包空，谈不上帮撰写人挡设计矛盾。
- **截图**：`screenshots/11-总体设计已填-可完成第一步.png`，`screenshots/13-PICOS设计页.png`

### S-3 竞品相关性

- **做了什么**：先看自动检索，再点「未找到结果，重新检索」，后把 ClinicalTrials.gov 检索词改成 `postmenopausal osteoporosis`，打开竞品抽屉，把筛选从「已保留参照」改成「全部状态」，点 NCT01796301 标直接竞品并锁定。
- **看到什么**：
  - 第一次用中文「绝经后骨质疏松症」当注册库条件，0 条。系统自己也写「中文适应症可能降低英文注册库检索精度」，但重试仍用中文，界面没有改检索词的入口。
  - 英文词之后：API「返回 146/146」。里头有该有的：romosozumab（NCT01796301）、denosumab/Prolia、abaloparatide、特立帕肽、阿仑膦酸钠。也有不该挤进 III 期硬骨抑素篮子的：大豆异黄酮内皮功能（NCT01463436）、乳腺癌内分泌治疗相关骨丢失 ZFAST（NCT00050011）。
  - 顶部仍写「公开检索未发现可保留Protocol」，同时另一处写「已结合 146 项公开研究及 17 份Protocol」——同一屏两种说法。
- **结论**：英文检索后，骨/PMO 大方向对；分诊没自动跑完，全是「待AI分类」。相关的能找到，不相关的也会混进来。锁定后 NCT01796301「未发现公开 Protocol」，深度处理停死。
- **截图**：`screenshots/10-竞品检索-结束.png`，`screenshots/17-竞品146项待分类.png`，`screenshots/19-无公开Protocol待手动导入.png`

### S-4 PICOS 一致性

- **做了什么**：在 PICOS 六个子页手填人群、入排、干预、对照、终点、统计。
- **看到什么**：系统没有按基准卡预填。入排要自己点「新增入选/排除」。低钙监测、心血管排除、背景补钙+维生素D，都是我写进去的，不是系统提醒的。主要终点我写成「第12个月腰椎 BMD 较基线变化百分比」，并注明联合主要可加新发椎体骨折、主比较对安慰剂。
- **漏了什么（系统没拦也没问）**：椎体骨折史分层、严重低钙入排阈值、心血管排的时间窗是否统一、阳性对照臂的盲法双模拟细节（有补充栏可写，但不是必填结构）。样本量只让写策略，没有 N。
- **结论**：PICOS 表单能承载一份 III 期骨药设计，但要撰写人自己当主笔；系统没有把基准卡里的关键项变成默认条款。

## 逐环节感受

**首页**：干净，像一个项目收件箱。没有 monitoring_principal_unavailable。旧项目很多，下拉很长，容易误触（我填建项表时曾把顶栏项目下拉误选到 R3A-BPH101，随即创建自己的 R4D- 项目，没有打开或改那个旧项目）。

**从零建项**：弹窗清楚，入口A默认就选中。缺项目名栏，只能把 R4D- 塞进药名。分期下拉有 III期。创建后马上进医学写作。

**写作落地页**：第一眼就是黄条 500 和「尚未建立可编辑章节」。对撰写人很差——我还没开始写，编辑器已经说会话坏了。

**研究设计抽屉**：信息密度很高，步骤条、竞品条、AI 推荐、高级微调叠在一起。AI 推荐长期空包，还把 `design模块待AI基于语料生成` 直接显示给人看。真正能干活的是下面那排「项目与产品 / 研究目的 / 竞品范围 / 总体设计」。

**事实采集**：最失望的一环。我把几乎整份方案摘要喂进去，它既不拆事实也不追问，最后甩一行英文内部错误。

**竞品**：中文检索像没查；英文检索一下子 146 条，默认筛选又让人以为是 0。分诊要手点。锁定后发现这份 romosozumab 研究没有公开 Protocol，唯一出路是「手动导入」，而本场景不允许上传。条幅说可以「共享语料或记录例外」，抽屉里找不到这两颗按钮。

**PICOS**：像一份很全的内部设计表，随机化/盲法/DMC/AESI 都有。撰写人能把 III 期骨架填进去。对照类型不能同时表达安慰剂+阳性，别扭。

**初稿/导出**：没走到。目录空、版本空、证据 0 条、没有 Word 按钮。

### 易用性 / 逻辑性 / 美观性

- **易用性**：建项简单；设计抽屉太深，必填分散在多个 Tab；检索词改了不会自动用到第一次检索；「完成第一步」后改 PICOS 还要回来再确认一次。
- **逻辑性**：中文适应症打英文注册库得到 0，和系统自己的提示打架；「0 条可保留 Protocol」和「已结合 146 项/17 份 Protocol」打架；写作 500 与「当前阻断写作」两套失败同时出现。
- **美观性**：康哲风、步骤条、卡片都整齐。空态和英文报错破坏专业感。内部标识符直接上屏，像后台没关干净。
