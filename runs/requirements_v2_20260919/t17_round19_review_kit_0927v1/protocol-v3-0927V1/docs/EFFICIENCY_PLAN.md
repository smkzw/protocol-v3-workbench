# 0927V1 开发与验证执行方案

## 结论与边界
改变执行结构，不更换产品架构。保留pytest/Vitest/既有浏览器工具、原有持久任务和证据规则；将频繁小反馈与昂贵真实模型/发布验收分开。流程不是越长越安全，测试不是越少越快：应让每次反馈既便宜又能定位根因。上一轮“修可信测试门”的要求不应升级为“全库历史债务清点完才允许继续功能”。

## 时间模型与目前证据
一次周期=环境定位/安装+服务准备+模型准备/排队+测试准备/收集+测试执行+失败定位/修改+再验证+报告。并行阶段的和不是端到端时长。
仓库g1_step6_gate_final.json记录pytest elapsed=2958.1s、ran=11043；这是约49.3分钟的该次pytest执行，不包含每项其他准备时间，也不是每次固定时长。HANDOFF给出1–3小时是Agent自报范围。当前缺统一阶段计时，不能断言耗时80%来自模型或承诺提升10倍。

## 三车道与阻塞边界
|车道|运行内容|是否真实模型|触发|阻塞什么|
|---|---|---|---|---|
|FAST|语法/静态、纯逻辑、临时SQLite、API契约、改动所属模块及相关安全哨兵|否，外部网络拒绝|每次局部变更|当前功能包，不能豁免安全失败|
|REPLAY-INTEGRATION|真实前后端/状态/文件，外部provider与检索边界受控回放|否|UI、服务接线、恢复/版本等相关修改|对应业务路径|
|LIVE-EVAL/RELEASE|固定模型代表集、必要Word/UI全链及发布全回归|是，显式配置|模型/prompt/chunk/source/关键导出改变或发布候选|相关能力与发布，不阻塞无关离线功能|

全库是固定候选的一次广覆盖，不是每个red→green循环的开始。纯代码反馈目标可先设P95≤5分钟，先测后调；它是验收预算而非本轮实测承诺。未知依赖映射扩大测试到所属模块；变更共享contracts/runtime/gateway时跨模块检查。不得用仅--lf证明范围完整。

## 隔离与复用
- 锁定Python/Node和依赖；锁未变则复用现有环境，不重装、不下载全部浏览器。uv缓存是可选改进，不强制把requirements项目迁移到uv。
- 所有离线测试使用合成、私有runtime/config/DB/artifact/temp；进程环境白名单，不继承现场WORKBENCH_*、provider凭证或代理。配置必须在应用模块导入前设置。
- 用tmp_path/私有test run root隔离写状态；session级只能共享明确不可变的昂贵fixture。并行worker各有DB、端口、artifact、log。不要用产品目录作pytest --basetemp。
- 常驻开发服务可复用；验收固定候选独立实例。reuseExistingServer只是允许复用，还要验证源码/配置/数据根/所有权。不能连接到“碰巧同端口”的服务。
- test复用不等于结果复用。环境复用看工具链配置；结果复用看代码/fixture/依赖/源/合同身份。

## 模型分工与冷启动
只读doctor不应发chat请求；模型能力probe与warm-up是有成本、有副作用的动作。不要每个Agent会话启动时都唤醒全部角色。离线及回放测试不依赖本地模型。真实评估按角色集中运行，保留已驻留实例；确需切换时由一个资源所有者协调，检查在途任务与授权。
phase_model_readiness在当前源码忽略phase并warm两端；本轮未证明它被生产调用多少次。现场30GB估值不能单独证明128GB必然互斥，实际还要看KV、上下文、并发、系统压力。默认遵守现场既有约束，不能越权试验。

## 可重复的测试起点
建议的fixture不是另一个产品数据库：
1. 摘要输入与提取候选（明示合成、原始来源可查）。
2. 核心设计确认后的业务记录。
3. 600项注册元数据，不下载或翻译，验证20–30项选择。
4. 一个有Protocol/SAP/ICF类型反例的文件元数据集合。
5. 原文、成功/错误模型响应、完整对齐单元和版本身份。
6. 已保存DOCX工作稿及可编辑对象锚点。
由真实业务构建路径生成并验证，测试复制到私有空间。修改前置contract后失效或显式迁移，不直接SQL改状态为approved。发布保留从起点的完整双入口；日常保存测试不重做检索与翻译。

## 故障处理与测试卫生
按机制族诊断：导入路径/单例初始化、环境变量、live数据、时间/随机、线程泄露、固定tmp、排序/运行依赖、模型网络以及真实产品断言。先找失败前最短污染序列，不逐个重抄指纹。采集seed/顺序/失败call/teardown信息；先隔离再加并行，避免xdist放大共享状态。
known failure是带owner/issue/expiry/影响范围的债务；不能称永久豁免。baseline_commit与tested_commit分开并验证祖先/环境/依赖；正常HEAD推进不能强迫重采全部失败。新相关失败先修，本次安全范围不可known豁免；其他全库债务仍显示，开发允许继续不等于release已通过。

## 命令与报告的最小改造
继续扩展tools/acceptance/run_acceptance_gate.py，而非建立新门：为其增加FAST/REPLAY/LIVE运行计划（名称为拟议接口，当前尚不可直接调用），每个计划包含测试nodeids、选择理由、所需依赖、环境身份、fixture身份、必测清单及预算。权威报告输出到原子JSON文件；stdout给人看，禁止编排器靠GATE_JSON冒号/等号猜解析。失败后重读已保存的报告，不再跑整套来重新得到同一错误。
明确脚本root，拒绝多候选仓库。报告保存actual exit、collection/setup/call/teardown结果、未运行节点、重试/skip、日志位置。超时保留部分输出且结论为中断，不冒充零失败。

## 人员/Agent编排
同根因、同接口的修复聚成一个小功能包，包内快速red→green；包尾独立复核一次。跨模块共享文件单一集成人，其他工作树隔离。已有报告一次读取多人复用，不让多个测试Agent各自重装、启动同一服务或执行同一全库。
不要求无限串行G0→G7：可信FAST建立后，G2/G3/G4继续按依赖推进，G6元数据与G7界面可并行。全库卫生是一条有边界的债务车道，不把所有人堵在基线文件上。

## 可量化验收
每个修改周期记录env/install、boot、model_load、model_queue、collection、setup、test_body、generation、retry、fix、report的单调时间戳和run_id。三次真实周期后比较：修改到可信反馈的P50/P95、未变环境的重启次数、重复模型调用数、same-root-cause重现次数、业务正向闭环数。日志不记录密钥或临床正文。没有数据就写未测，不编造收益比例。

本包junit_profile.py只读JUnit，输出慢用例与错误族，明确case_time_sum不是wall-clock，也不拿class/name替代真实nodeid；它不是新验收门。
