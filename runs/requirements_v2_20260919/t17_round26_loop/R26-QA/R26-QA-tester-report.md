## 二、每个环节的感受（真实用户操作视角）

- **建项**：三项即建，快。但建完立刻发现不能改名（项目列表里找不到任何重命名入口，只能进"高级微调→项目身份"里改字段，且改完列表不跟）。
- **事实采集**：这是全程最好的体验。AI把我的自然语言拆成逐字段卡片，每张标注"用户明述/AI推断/存在冲突"和置信度，我可以逐条采用/修订/拒绝；它还主动识别出"R26QA-TP021 vs KM-2101"冲突并提问。缺点：解析等待久（1~6分钟）且无排队提示；点快的卡片会卡死（P1-3）。
- **研究框架**：字段分租合理（项目身份/总体设计/PICOS），必填带*。"适应性设计/SRC/DMC/期中分析"强制选"计划/不计划"、禁止"待确认"，作为注册QA我很认可——这正是监管核查常抓的点。
- **竞品调研**：检索条件、分诊线索（TPO-RA/成人慢性ITP/small_molecule/口服/systemic）回显清晰，可审计。"无公开Protocol→确定性排除"的规则坦白说明了"不等同于否定其临床研究价值"，合规上站得住。
- **语料处理**：从这开始体验断崖。下载无任何进度反馈；解析报错后无重试指引（OCR密钥是环境问题，但界面只甩一句"操作未完成"）；横幅里还残留首次检索失败的旧警告，与新结果自相矛盾。
- **PICOS设计**：字段专业（估计目标策略、样本量策略都在），规则自动编号（IN-/EX-/BG-/CM-A-/WO-/TIME-）很规范。但"研究臂/队列"点"其他/高级微调"后跳到的面板里根本没有这个字段，"暂不确定"又不被接受——我作为用户被系统锁死，找不到任何出路说明。
- **导出**：从未见到导出按钮。

## 三、三句式评价

- **易用性**：AI事实拆解的逐项确认、必填*标记、规则自动编号都好用；但"N项必填待确认"从不告诉用户是哪几项（我靠逐面板排查才定位到"研究臂/队列"），高级微调面板频繁自动折叠、字段与编辑入口对应混乱，等待无进度提示，整体在"知道下一步该点哪"这件事上失分明显。
- **逻辑性**：事实→框架→PICOS→语料→写作的主干符合真实医学写作工作流，分诊确定性规则透明可审计；但"语料例外放行要求PICOS完成、PICOS完成要求研究臂字段、研究臂字段又依赖语料准入的AI生成"构成循环死锁，逻辑上自我锁死，缺少任何一条人工兜底路径。
- **美观性**：CMS橙白风格统一，步骤条/抽屉/表格规范，状态色（橙=进行、绿=完成）一致，整体专业；扣分项是界面直接露出内部状态码（design_recommendations_blocked:research_pipeline_awaiting_corpus_admission）、项目列表仍显示旧药名、个别占位文案张冠李戴。

## 四、缺陷分级

### P0（阻断标准链路，必须优先解决）
1. **OCR环境缺配置导致语料链死锁**：解析R788 Protocol报"操作未完成：OCR API Key is not configured for the Paddle provider"（截图13）。Protocol无法解析→中文译文无法生成→语料无法准入→"design模块待AI基于语料生成"，证据化设计与方案生成全部冻结。环境配置问题，但系统应提供明确的"环境不可用"提示与恢复指引。
2. **"研究臂/队列"无编辑路径 + 例外放行死循环**：第二步必填项"研究臂/队列"——AI候选被语料门阻断（"候选内容待生成"）、"其他/高级微调"跳转到的设计适用性面板中无该字段输入、"暂不确定"暂缓后必填计数仍为1、"采用"按钮禁用；同时例外放行报"study framing and PICOS must be complete before corpus override"。两条路互为前置，用户被永久锁死（截图27；异常文案在会话内录得）。

### P1（功能受损/误导，需修）
3. **事实卡片UI-后端状态不同步**：已决策的卡片仍显示"采用"按钮，点击报"事实应用失败：fact intake proposal not found or already decided: p001/p018/p019/p020/p023"（5张卡复现），卡片永远无法从列表消除，且混在待确认列表中阻断顺序操作（截图10）。
4. **首屏项目列表误报"暂无项目"**：项目数0、空态文案"新建项目后开始医学工作"，实际存在14+个既有项目；新建项目后列表才全部出现（截图01）。

### P2（体验/一致性）
5. **药物改名不贯通**：字段改名R26QA-TP021并保存、AI确认后，顶部项目选择器与项目列表仍显示"KM-2101"（截图23/26）；AI事实引擎把系统内改名误报为"产品标识冲突"需人工确认。
6. **内部状态码外露**："来源限制 design_recommendations_blocked:research_pipeline_awaiting_corpus_admission"直接显示给用户。
7. **下载/解析无进度反馈**："下载并解析"点击后按钮无变化、无toast，实际后台已下载（状态变"待解析"），用户会重复点击。
8. **竞品调研横幅自相矛盾**：重检索获得129项后，横幅仍显示首轮"未发现可下载的公开方案…0/4"，直至刷新页面。
9. **分诊匹配维度显示矛盾**：R788研究（标题即Persistent/Chronic ITP）的"适应症"维度显示"不匹配"。
10. **首轮自动检索用中文适应症名**：建项后自动检索返回0/0；完成事实采集拿到英文标准词后才检索成功——首轮应直接使用规范英文词或至少给出"检索词不规范"提示。
11. **占位文案错位**：文献侧栏"可说明已核对的原始页面或确认依据"出现在不相关输入框（适应性设计自定义输入旁）。

### 值得保留的亮点（QA视角）
- AI事实拆解：逐字段确认+置信度+冲突识别+高影响缺口清单+按下游影响排序的追问，符合"数据可溯源"要求。
- 反伪造约束：未知定量字段（FIH起始剂量等）坚持UNKNOWN不作推断；无候选时明确"不会伪造上传或公开来源"。
- 分诊确定性规则透明："该结论不等同于否定其临床研究价值"。
- 变更管理：确认前列出"该变更会使下游内容失效"的13个下游对象清单并要求重新核验。
- 引文格式默认GB/T 7714-2015顺序编码制，符合国内注册申报习惯。
