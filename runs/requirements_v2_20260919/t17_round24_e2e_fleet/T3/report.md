### 2. P1｜运行环境阻断页面 `<main>` 容器布局重叠遮挡左侧全局导航栏
- **严重级别**: P1（交互严重缺陷，破坏用户界面基本导航能力）
- **现象描述**: 
  在“当前版本组合不可进入写作工作区”阻断页面中，主容器 `<main class="page writing-runtime-gate-page">` 的 CSS 坐标为 `x: 64px, y: 72px, width: 1664px`，而左侧主导航栏 `<nav class="nav">` 的坐标为 `x: 0px, y: 72px, width: 180px`。二者在 `x: 64px ~ 180px` 区域内发生物理重叠。由于 `<main>` 在 DOM 树后方且处于 static 定位流，导致左侧主导航按钮（如“证据调研与方案设计”、“医学写作”等）被 `<main>` 完全遮挡。当自动化或用户点击侧边栏导航按钮中心（x=90px）时，浏览器直接报错：`<main> intercepts pointer events`，用户无法直接通过左侧导航切换模块，必须依靠左上角极小区域的“返回项目总看板”脱离阻断页。
- **复现步骤**:
  1. 处于医学写作阻断页（`writing-runtime-gate-page`）。
  2. 点击左侧导航栏中的任一模块按钮（例如“证据调研与方案设计”或“医学写作”）。
  3. 观察到点击事件被 `<main>` 拦截，无法发生页面跳转。
- **证据截图**:
  - `screenshots/06_after_recheck_wait.png`（阻断页全貌）
  - 控制台报错日志: `Locator matched 1 elements, but none can receive input; <main> intercepts pointer events`

- **严重级别**: P2（界面易用性与数据纯度缺陷）
- **现象描述**: 
  在“新建研究方案项目”弹窗中，只有三个输入项：“试验药物”、“适应症”、“研究分期”，没有独立的“项目名称”或“项目标识”字段。按照测试规范要求项目名称带 `T3-` 前缀以便在多项目环境中唯一识别，测试者只能将 `T3-` 强行填入“试验药物”输入框（即填写为 `T3-FXIa-01`）。这导致药物本身的命名实体被混入了测试管理标识符，若后续用于撰写，可能直接污染临床试验方案正文中的受试药物称谓。
