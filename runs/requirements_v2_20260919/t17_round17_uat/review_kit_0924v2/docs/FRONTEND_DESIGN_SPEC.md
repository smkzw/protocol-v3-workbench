# 0924V2 医学写作前端与AI工作区

## 核心原则
用户操作是“资料与设计 → 工作稿 → 修改”，不是观看内部流水线日志。页面尺寸设计是建议，须以1440/1920/2560实际截图+DOM验证；本轮未做实时视觉测量。
复用当前组件、full-draft-review-workspace与GenOffice实例；不要为布局重建编辑器、清选区或丢dirty。不得通过全局hidden/裁剪/小字掩盖信息。

## 页面分工
1. 资料与研究筛选：使用主工作区完整宽度。顶部显示检索研究数/去重数/入选研究数/方案文件数；中间为紧凑筛选表；侧边或宽详情抽屉说明单研究依据。默认显示入选，备选/已排除可查看。
2. 研究设计：主区并排2–3个真正可比的选项；关键科学决定集中显示，来源、局限、差异就在同一个阅读面展开。不要把整套设计文本塞入右栏。
3. 初稿生成：主区已有工作稿/候选继续可读；顶部一个主状态条，任务与缺口分开。已完成/进行中/待补充/失败分别计数。
4. 正文编辑：正文占主宽度，AI右栏只承载当前任务摘要、当前选区指令、待处理建议和状态。复杂候选/长证据进入宽审阅面。章节导航可折叠。

## 尺寸与阅读
- 普通右栏建议400–520px，可调宽且记住会话偏好；1440宽时优先收起次要导航，不缩小所有字。
- 展开候选的阅读面建议680–960px或可切换主区宽审阅模式；已有全稿审阅层优先复用。
- 桌面窄于1440不作为首要优化目标，不需要重做移动端。本次验证1440/1920/2560三档。
- UI小字>=12px；阅读正文>=14px。原生Word的字号与页面缩放按文档模型/用户缩放处理，不以CSS强行改稿件字体。
- 卡片不设112px内嵌正文滚动；摘要层可折叠，但正文完整可展开。每个面板一个主滚动容器，按钮固定在可见页脚；禁止多层小滚动框。
- 来源正文允许英文、NCT/药物代码/DOI保持原样；禁止的是原始异常、内部stage/code/id直接成为默认中文提示。

## 右栏结构
当前对象：章节/段落/表格/选区，明确修改范围。
主动作：一个自然语言输入+执行，不并排堆多个意义相近按钮。
建议摘要：建议做什么、关键变化、影响、状态；“展开完整比较”到宽面板。
来源/待核对/历史以三个标签页或分组切换，不一次铺满。
工作稿已保存与科学待核对并列，不使用单个绿色“完成”吞掉差异。

## 公共状态合同（建议扩展现有DTO）
public_status = {phase_code, display_state, title_zh, completed, total, unit, detail_zh, can_leave, actions, diagnostic_ref}
- title/detail由白名单模板+已校验参数生成；未知code使用安全中文总结，不回退到raw exception。
- 默认显示“正在整理研究方案：已完成8/25份；2份需重新取得原文。已完成内容已保存。”
- 诊断详情显式展开才显示code/request_id及脱敏技术说明。日志保留完整原错误，不能删证据。
- can_leave只有任务和待提交意图均有持久化恢复时为true；仍为仅本页意图则明确提醒并保留离开保护。
- actions由后端实际状态与权限提供；“重试”只重试目标失败且可恢复，“取消中”不显示已取消，“结果未知”不清操作身份。
- queued/running/partial/failed/completed为技术状态；资料就绪、工作稿可编辑、待科学决定、可交付是独立业务状态。
- 文件/章节/任务数量不能混成同一分母。翻译candidate_ready与通过忠实度/已人工确认分别显示。

## 源码接入点
frontend/src/App.jsx：writing-layout、writing-ai-core、full-draft与revision进度显示。
frontend/src/styles.css：双列宽度、ai-rail、候选112px滚动/13px字体、隐藏来源块、窄屏覆盖规则。
features/medical-writing/MedicalWritingAuthoringJourneySetup.jsx：研究设置、任务等待、原始错误提示、筛选进入。
features/writing-reference/WritingReferencePanel：研究表、文档列表、范围与批次状态（Agent先核实实际子组件，不凭名称改所有文件）。
features/medical-writing/protocol-workbench/ManuscriptWorkspace及office：统一当前稿、来源和任务提示；不能另开第二可写全稿。
后端research_pipeline、preparation_batch及translation_batch：结构化状态与中文展示层，保持内外错误分离。

## 视觉验收
实际卡片可读宽度、关键内容完整展开、长中文与英文题名/DOI不外溢；无正文112px嵌套滚动；按钮关闭可点；等待/失败/缺资料/候选/冲突都有正确出口；展开/收起/改宽/切标签均不重建iframe；失败状态截图与已完成状态分开。不要仅用DOM无overflow代替视觉美观，也不要用漂亮截图替代功能验证。
