# 0924V2 研究筛选与Protocol-only实施规格

## 1. 单位与边界
- 检索记录、去重后的研究、药物研发项目、文件、文件版本、章节/译文片段分别计数。
- 本轮“20–30”指不同研究，建议默认25、默认上限30；用户明确扩展时展示范围并创建新版本；合格研究<=30时全保留，不作纯预算裁减。质量/相关性和文档类型排除始终生效。
- 同一NCT多个协议版本不是多项研究；同一研究在多个注册库出现需跨注册号对照。无法确证同一研究时保留疑似关系，不能强行合并。
- 不为凑25项补入无关研究。21项足够好就21项；无可用公开方案则标记，不自动拿SAP代替。
- 备选池只存元数据，未替换进shortlist前不得预下载/翻译/深分析。总预算与每批大小、并发数、模型重试预算无关。

## 2. 推荐流程
广检元数据 → 去重与基础适用性 → 元数据层相关性/未知信息补足 → 透明排序和多样性选择 → 默认选中20–30研究 → 每研究优选方案版本 → 冻结范围 → 下载/抽取 → 方案范围确认 → 关键章节翻译及语义提取 → 对设计问题形成候选。
不把数百篇全文先下载翻译后再筛；也不把相关性分诊中的direct/indirect等同本轮深读入选。

## 3. 筛选维度与优先关系
第一层：同适应症及可比人群（分型、严重度、年龄、治疗线、既往治疗/难治性、单药或背景治疗）；相关性不足不能靠新近或中国中心补分。
第二层：分期+真正目的。PhaseII剂量探索最优先；II/III有可分离II部分其次；同一期但目的不同仍需降序。III期可补终点及监管路径，不可挤掉主要II期设计。
第三层：药物技术类型、给药途径、局部/全身、机制。口服小分子与外用小分子不等价；单抗也应区分抗体类型和途径。注册DRUG/BIOLOGICAL大类不足以作精确类型证据。
第四层：比较组、背景/救援治疗、疗程、访视、终点量表和评价时间、随机/盲法/多中心等设计相似性。
第五层：设计新近程度、中国参与中心、经核实的获批关联。新近以研究/方案形成时间为主，FirstPosted只能作次级代理；LastUpdate不当研究年代。中心记录应来自实际location/可核验项目资料，不由申办者名称推断。中国含区域的原始标记应保留，不把多区域不同记录粗暴覆盖成同一行政标签。
第六层：设计可读性/资料完整性、独特设计和代表性。全文可得优先，但高价值无方案研究保留元数据备选；一个药物项目/申办者的高度相似试验不垄断名额。保留少量确有借鉴价值的失败/终止研究，避免只学成功赢家。

## 4. 获批关联的严格含义
批准是产品针对适应症与获益风险证据的决定，不等于每个开发期研究每项参数都被监管认可。
必须记录监管机构、批准适应症、批准日期、可查来源、当前研究与批准资料关系（关键支持/其他支持/仅同研发项目/未知）。“新上市创新药”不能由上市品牌名或模型记忆自动推断。
允许读取官方批准网页/注册元数据核对选择依据；它们不进入本轮Protocol翻译语料。默认不为了验证批准而再批量下载其他文档。

## 5. 分数与组合
不建议把未经验证的总分当质量真值。先设相关性档，再在可比候选中以透明维度排序；初版可用配置化权重，但须标为工程排序，不是临床证据等级。unknown与mismatch分开，不以缺字段判没有中国中心。
默认25项中，多数为同分期/同人群/同类型直接参考；其余补中国执行、已批准项目对应阶段、方法学差异和少量反例。比例为软覆盖目标，不机械定额；稀少场景不强求全部槽位。
每项展示最多3条最强入选理由、1条主要差异，以及来源展开。用户可一屏核对/替换整组，不强迫25次单项批准。

## 6. 数据与执行合同
扩展已有snapshot、triage basket、preparation scope，不创建第二权威数据库。
shortlist至少记录id/revision、project+study facts hash、search snapshot、规则版本、eligible_count、目标数/上限、selected study IDs、reserve IDs、每项理由和证据、推荐/手工替换来源、source manifest hash。
下载范围另固定document ID/type/version/url、文件选择依据、是否合并包、已知排除范围。最终content hash在取得字节后绑定；不能假装下载前已有文件哈希。
所有下载（批量/单文件/自动续批/失败重试）、翻译和深读worker调用同一scope guard。重复任务键包含shortlist和document scope身份；不能只用snapshot_id复用旧全量批次。
更改shortlist创建新版本，仅在安全边界处排除尚未开始工作；在途任务不暗改输入，已完成工件只读保留且标记当前是否采用。范围外项目不记“失败”，也不占待人工处理数。

## 7. 文档策略
优先适用的独立完整Protocol；默认选取可核验的适用完整版本，涉及原始设计或关键修订时记录对应历史版本，不混成单一设计。独立SAP、ICF、CSR、IB、论文、海报及其他文件不进本次竞品Protocol下载/翻译/设计分析主链。
只有合并Protocol+SAP时，可取该合并包来取得Protocol部分，界面标“研究方案（合并文件，仅处理方案部分）”，建立可靠范围，SAP正文不得送入翻译/深读。存在同版本独立Protocol则不再取合并包。
“方案内统计分析章节”“方案内知情同意程序”仍然是Protocol内容，不能按关键词SAP/consent删除。对标错或unknown文件先元数据/有限结构校核，无法确认的不当作Protocol；已经取得的错标历史文件隔离保留，不继续分析。
服务端根据scope核查文档类型，不能仅靠前端隐藏按钮。通用下载入口需要显式purpose和统一allowlist，避免批次正确、单文件路径绕过。
文件名标签不等于下载事实：UI应区分发现元数据/未下载/已缓存历史/本轮采用/排除，不将搜索结果列表误报下载清单。

## 8. 翻译与错误处理
一份入选Protocol在版本/hash/语言与处理合同相同条件下复用成功结果。关键内容至少覆盖目的终点、设计、入排、干预/对照/背景及救援、访视、停止退出、安全、统计；有依赖时保留脚注/表格和相邻定义，不要求无差别全文逐字翻译。
技术失败、截断/无效JSON、抽取边界错误、忠实度错误、非目标片段、真正医学未决分开统计。
每类选代表原文+译文+差异位置分析。轻微格式噪声修验证器且保留语义反例；真实数字/单位/否定/人群/时点错误不得豁免。缺口保持可定位，不为了获得“0 blocked”清空或伪批准。
预算耗尽的原任务不可改写attempt历史；基础设施修复且任务仍在本轮范围时，新建受控恢复尝试关联原任务，保持业务去重、费用边界、成功片段复用。优先诊断根文档/章节，不把几十个派生失败当几十个独立模型问题。
