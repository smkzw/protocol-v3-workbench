## 3. 问题清单（P0 / P1 / P2）

### P1 级缺陷（严重影响体验或内部标识泄漏）

#### 【P1-1】对话式事实采集报错泄漏内部字段名并阻断采集轮次
- **现象描述**：在“研究框架 $\rightarrow$ 高级微调 $\rightarrow$ 对话式事实采集”输入自然语言意图并点击“提交并拆解”后，前端状态栏直接暴露内部校验规则与类字段名：
  `事实采集未完成：fact intake proposal[11] exact high-impact field framing.product_profile.confirmed_facts.treatment_interval must be explicitly user_stated or source_extracted`
  导致本次自然语言输入未能展示结构化待确认卡片，破坏对话式采集体验。
- **截图路径**：`/tmp/t17_r12_tester2/27_fact_intake_leak_error.png`
- **复现步骤**：
  1. 新建项目进入“研究框架 $\rightarrow$ 高级微调 $\rightarrow$ 项目与产品”；
  2. 在“自然语言事实输入”框中粘贴包含给药周期但未显式标注给药频次的段落；
  3. 点击“提交并拆解”，等待模型解析返回，页面立即弹出包含 Pydantic 校验路径的英文错误。

#### 【P1-2】研究流程图“插入方案”端点因未自动同步 Assembly Plan 版本报错
- **现象描述**：在“研究示意图”中点击“生成候选图”，点击“确认全部候选”，填入变更理由后点击“插入方案”，系统报错：
  `插入方案失败：plan revision 3 for project proj_user_5354f3dc97d7 is stale relative to the source StudyDefinition`
  后端端点在执行插入方案前，未先触发 `protocol-assembly-plan/refresh`，导致前序设计变更使计划版本落后于当前定义版本而失败。
- **截图路径**：`/tmp/t17_r12_tester2/103_flowchart_inserted_into_protocol.png`
- **复现步骤**：
  1. 完成研究框架与 PICOS 设计并更新过设计事实；
  2. 进入“1.2 研究示意图”，点击“生成候选图”并“确认全部候选”；
  3. 输入合规理由后点击“插入方案”，页面抛出版本过期错误。

#### 【P1-3】绿地文档在版本隔离面板点击“恢复权威源基线”报错技术阻断
- **现象描述**：当研究设计更新导致已有绿地文档被隔离后，用户在“版本与恢复 $\rightarrow$ 隔离历史”输入恢复理由、勾选确认框并点击“恢复权威源基线”时，前端弹错：
  `版本恢复失败：intrinsically bound greenfield documents must use StudyDefinition rebind`
  系统未自动将绿地文档的基线恢复意图路由到 `/study-consistency/rebind` 端点，而是暴露了底层代码技术限制文本。
- **截图路径**：`/tmp/t17_r12_tester2/109_baseline_restored.png`
- **复现步骤**：
  1. 建立绿地文档后返回调整 PICOS 并提交变更，触发文档一致性 `stale`；
  2. 打开“版本与恢复”抽屉，展开“隔离历史”，填写恢复理由并勾选知情；
  3. 点击“恢复权威源基线”，界面显示错误提示。

## 6. 已知局限（KNOWN_LIMITATIONS）

1. **大体量全文生成周期较长**：全文初稿任务切分为 21 个批次（共覆盖 80+ 章节正文），由于每个批次需携带详尽事实约束并调用大模型生成数千字监管规范正文，端到端耗时通常在 20–30 分钟。当上游网关出现瞬时超时时，系统具备 fallback 容灾能力，但会进一步拉长整体等待时间。
2. **零资料起步正文导出强约束**：系统严防“空白空心方案”流出，在全文初稿尚未生成并采纳至工作副本前，Word 导出（包括草稿预览）会执行强校验并阻断，必须完成初稿补全与采纳。
3. **流程图与装配计划版本联动机制**：在快速多轮调整设计事实后，前端流程图提交端点对装配计划版本严格校验，若计划未自动刷新会导致保存受阻，建议在后端增加原子化预检并自动触发 `assembly-plan/refresh`。
