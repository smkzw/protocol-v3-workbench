# Protocol v3 全文初稿 v0.5–v0.9 阶段复盘

日期：2026-09-22

## 结果

本阶段把全文候选从“有证据但大量预写和重复确认”推进到“数字事实稳定、缺口大体诚实、点击面显著收敛”。v0.9 的 44 complete / 1 decision_required / 40 source_gap 比 v0.8 的 70/3/12 更保守，但更符合真实医学写作：缺 IB、PV、药学、运营、伦理和保险材料时不再用通用段落假装成项目正文。

## 做对的事

- 持久化 evidence binding，并在 chunk 恢复、最终合并、读取和采纳前重复核验。
- 把决定卡从 73 张压缩到两个真实字段，且确认前正文为空。
- 不用盲法、妊娠、AE、剂量、计划外访视等通用规则填补项目缺口。
- 保留一个统计升级，不恢复 21 个空确认壳。
- 真实运行始终使用用户指定产品模型，独立医学审阅使用不同模型身份。
- 以完整版本批集中测试，没有恢复“改一处测一次”。

## 踩坑

- v0.6 的确定性降级过宽，47 个 source gap 失去大量可写事实；后续改为只拦明确具体规则。
- v0.7 通过访视日推断安全检查、DLQI 和妊娠规则，说明只靠模型提示不足。
- v0.8 删除空 required 时把唯一统计升级一起删掉；减少点击必须保留真正的科学决定。
- v0.9 仍把公司语料写成项目义务，并把体格检查放进安全性终点；来源类型与标题语义都需要确定性验证。
- 集中测试第一次缺 `tests` PYTHONPATH，第二次暴露旧 schema fixture。最终修复的是测试迁移，不是降低产品约束。

## 下一阶段原则

先解决四类明确问题，再生成 v0.10；不要继续靠增加提示词堆砌规则。优先增加来源类型感知的最小验证和跨字段原子决定。v0.10 医学会商通过前不做 Word 采纳、浏览器成品验收或三研究完成声明。
