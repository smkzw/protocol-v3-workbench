## 1. 测试场景与入口定义

- **疾病领域**：复发缓解型多发性硬化（RRMS），II期临床试验。
- **试验药物**：合成药M8（口服新一代选择性S1P受体调节剂）。
- **关键方案设计**：随机、双盲、安慰剂平行对照，多中心，疗程24周，计划约200例（1:1分组，各100例）。允许受试者维持既往稳定的背景注射干扰素β（IFN-β）。
- **主要终点**：治疗24周时的年化复发率（ARR）与治疗24周时脑部MRI钆（Gd）增强T1病灶累计总数（共同主要终点）。

## 4. 缺陷与体验问题清单 (P0 / P1 / P2)

### P1 级缺陷（严重影响体验与规范）

#### 【P1-01】内部架构标识符直接在UI视图中泄漏 (Leaked Schema Identifiers)
- **现象描述**：在第一步研究框架“展开单字段修改与依据”以及第二步PICOS“依据与局限”详情展开卡片中，内部数据模型和schema路径以原始英文标识符形式直出在用户界面中。
  - 示例 1：`study_definition · framing.investigational_product`
  - 示例 2：`study_definition · framing.indication`
  - 示例 3：`study_definition · framing.study_phase`
- **复现步骤**：
  1. 新建项目进入 Step 01 研究框架。
  2. 展开“方案标题”候选下方的“依据与局限”。
  3. 观察 `<small>` 标签中直接显示代码变量路径。
- **截图路径**：`/tmp/t17_r15_tester2/40_title_candidates_and_evidence.png`
- **建议**：应做用户友好化本地化文案映射，例如展示为“来源于：项目事实 · 试验药物名称”。

#### 【P1-02】科学设计校验阻断信息直出内部验证器错误编码
- **现象描述**：在Step 03点击“进入写作平台”时，若存在设计要素缺口，全局状态栏弹出原始英文校验器路径堆栈：
  `建立工作稿失败：protocol assembly plan still has unresolved scientific design blockers: evidence.systemic_oral_defaults, intervention.active_comparator_regimen, intervention.background_treatment, intervention.investigational_product_dose_actions, intervention.investigational_product_regimen, intervention.permitted_concomitant_treatment, intervention.placebo_regimen, intervention.prohibited_concomitant_treatment, intervention.rescue_treatment, product.route`
- **复现步骤**：
  1. 零资料绿地项目完成Step 01和Step 02基本文本录入，但未进入高级微调编辑结构化干预规则。
  2. 在Step 03点击“在保留全部缺口的情况下例外进入写作”并放行。
  3. 点击“进入写作平台”，观察底部红色报错。
- **截图路径**：`/tmp/t17_r15_tester2/74_after_retry_create_draft.png`
- **建议**：应将其转化为面向医学经理的可操作中文引导弹窗（如：“请先在PICOS干预措施中完善：试验药物给药方案、背景治疗规则与允许/禁止合并用药”），并提供一键跳转修复按钮。

#### 【P1-03】Pydantic/Value Error 校验错误信息直出未中文化
- **现象描述**：在结构化干预规则中选择“无计划性剂量调整”时，若未填说明，后台返回 HTTP 422 错误并在界面提示 `保存未完成：HTTP 422`，实际接口信息为：
  `Value error, no_planned_adjustment policy requires a nonblank no_planned_adjustment_statement`
- **复现步骤**：
  1. 在干预规则编辑器中选择剂量调整策略为“无计划性剂量调整”。
  2. 保持“无计划性调整说明”为空，点击“完成第二步”。
  3. 观察界面仅显示技术性错误码 `保存未完成：HTTP 422`。
- **截图路径**：`/tmp/t17_r15_tester2/120_dose_adjustment_statement.png`
- **建议**：前端应在此类必填项未录入时提供就地红色表单高亮与提示（“请填写无计划性调整说明”），禁止发出未校验请求。

### P2 级问题（交互体验与流程细节）

#### 【P2-01】竞品处理抽屉右上角关闭图标具有 `visibility: hidden` 导致无法直接点击
- **现象描述**：在打开“竞品方案处理”抽屉后，右上角关闭按钮元素 `.authoring-competitor-drawer-close` 具有 CSS `visibility: hidden`，必须点击半透明遮罩背景或按坐标规避才能关闭抽屉。

#### 【P2-02】全屏弹窗打开时导致后台元素整体 `inert`，缺乏焦点自动管理
- **现象描述**：当“研究方案目录”等对话框打开时，用户若尝试直接点击右侧栏“文献”或“版本”标签，浏览器因遮罩和 `dialog` 模态属性直接报 `element is hidden or inert`。
- **建议**：弹窗外点击应当自动平滑关闭当前非模态弹窗，或在视觉上对背景添加明显的模糊/压暗以提示用户需先关闭当前浮层。

## 6. KNOWN_LIMITATIONS

1. **零资料起步与深度竞品分析的耗时权衡**：
   从零开始时，公开注册库检索（锁定580项研究）和AI多批次分诊全量运行可能需要30-40分钟。若用户主动选择“取消研究流水线”，系统能够无损切换到以自然语言意图和手动锁定直接竞品（如Ponesimod）为主的事实驱动模式。
2. **全文初稿AI生成的生产级长耗时**：
   全套111个章节的初稿生成采用分批次深度调用（共21批），每批次需调用大模型完成临床合规写作与医学实体生成，单批次耗时约10-15分钟，全套生成需持续保持工作台运行。
3. **Word导出前置质量门禁**：
   工作台禁止导出包含大量未填充占位符的空方案；只有当全文初稿章节审核采纳完成或工作副本内容充实时，“正式 Word”与“预览 Word”才会放行下载。
