# 下一采用扩展：同源给药投影（待实施，不是新权威Plan）

已核现状：intervention.dose_regimen与picos.intervention_dose_regimen及其selected_regimen/route/starting/maximum/comparator等目前分别是legacy json。App.jsx医学写作入口仅传projectId，无studyDefinitionId/actorId。现有局部采用不可冒充跨章闭合或新建研究闭合。

## 最小实施顺序

1. 先给完整方案中的药品稳定身份及实际研究角色（研究药/对照/背景/伴随），同时保留阶段与组别；不要从名称含安慰剂、位于第一个组或数值0推断角色。旧已存提议读取兼容，缺角色时不生成看似完整的分角色投影。
2. 精确复用同一个完整给药对象；picos父路径和selected_regimen若语义确实等价，使用既有canonical_path别名。route/starting/max/对照为对同一对象的可追溯只读投影，不能复制成多套可独立修改的事实。
3. 多单位（mg、mg/kg等）、多药、负荷+维持/不同治疗期必须保留各自上下文。最大剂量不是简单max全部数字；选择的是计划研究方案对应药品/单位/时段的计划上限，临床暴露/最大耐受剂量不混淆。源模板4.3义务仍保留，不虚构固定剂量研究的递增逻辑。
4. 合同6.1.2的给药操作/暂停/降低/恢复/永久停药/漏给药继续从相关产品资料形成，剂量卡当前8步不代替这些事实。适用性控制沿现有布尔features；无DLT不索要DLT定义、未知不当false。
5. 真正RecommendationOption的理由、证据link、不确定性与影响仍待真实来源组织。当前hash option id只做采用身份绑定，不能称推荐选项持久化/医学准入已经完成。
6. App新建研究需绑定真实seed与用户确认事实。不要为了非空facts限制塞占位值，不拿integration_shared默认10mg或历史参考参数自动新建真实研究。待建项最小意图和首个实际用例明确后，复用既有create/application机制与稳定操作回执，不新造第二事实库。

验收反例：一种给药方案同时更新摘要/剂量依据/给药方案/统计治疗条件的同源读取；负荷量或继续期改动能定位真正受影响确认；整数/浮点、mg和mg/kg不混；对照无给药路径/单组设计按适用性处理；旧孤立dose文字冲突须显式裁定或保留为历史，不静默与新结构共存为当前事实。先验证实际副作用/用户流程再宣称完成。
