### Highest-impact defect (peer challenge)

**F-SS-01 is the highest-impact defect.** The sealed `NodeExecutionContract` includes `same_session_recovery`, but Task 1.7 harness/adapters never read it. Session resume is driven solely by non-null `provider_session_id`. That is a first-principles contract-binding hole: immutable contracts are only as strong as the fields the harness enforces. Tests currently exercise “session id forwarded ⇒ resume” without polarizing on `same_session_recovery=False`.

**Concrete alternative:** treat recovery as a three-state policy:

1. `same_session_recovery=False` → never pass session to adapter plan (strip/reject if present).
2. `True` + session id → resume path only.
3. `True` + null session → new dispatch (or fail if recovery was required — product choice).
