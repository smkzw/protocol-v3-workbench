**Defect 1 (functional, confirmed by runtime probe): raising credential resolver bypasses the safe probe receipt.** `_run_probe_once` catches only `ZhipuTransportError`, but the real Codex resolver raises `OmpCredentialError` on missing/empty store. Demonstrated: `adapter.probe()` with a raising resolver propagates raw `OmpCredentialError`, `probe_state.receipts == ()`, zero sink writes. Consequences: (a) the most important first-use failure (no credential) leaves no auditable `ZhipuProbeReceipt`; (b) direct-adapter callers see an untyped (for this module) exception instead of `ok=False` receipt + `False`; (c) only the harness wrapper converts it (`AdapterProbeError` → `probe_failed`), so observability depends on call path. The blank-string resolver path is handled (returns `""` → `ZhipuTransportError` → receipt), so this is specifically the *raising* path — i.e., exactly what the production resolver does. **Remedy:** widen `_run_probe_once` (or `_probe`) to catch `Exception` from `credential_resolver()` (and arguably from `_complete`) and record `ZhipuProbeReceipt(ok=False, error=<stable code>)`, preserving the existing `ZhipuTransportError` branch. Keep error text to the stable code (`omp_credentials_unavailable` / `temporarily_blocked` / `command_binding_unsupported`), never resolver internals. Test to add (Codex/worker-owned, not this review): raising-resolver probe returns `False`, appends exactly one receipt with `ok=False` and credential-free `error`.

**Defect 2 (functional, confirmed by runtime probe): `output_schema_ref` validated after a billable call and a durable sink write.** In `_dispatch`, `output_schema_ref` emptiness is checked *after* `_complete(body)` (HTTP) and `output_sink(content)`. Demonstrated: payload with `output_schema_ref=''` → 1 HTTP call fired, 1 sink write, then `ZhipuTransportError("dispatch payload carries no output_schema_ref")`. Unreachable via `HarnessDispatcher` ( `build_request` guarantees the ref), but reachable on any direct-adapter use; wastes a metered call and orphans a durable artifact on malformed input. **Remedy:** move the `output_schema_ref` non-blank check above `_complete` (alongside the effort check). Same-pass hardening: wrap `_compose_messages` artifact-key access so malformed `input_artifacts` raises `ZhipuTransportError` instead of raw `KeyError` (demonstrated: `[{'ref':'x'}]` → `KeyError: 'sha256'`); effort-before-HTTP ordering itself is already correct (demonstrated: bad effort fires zero HTTP).
