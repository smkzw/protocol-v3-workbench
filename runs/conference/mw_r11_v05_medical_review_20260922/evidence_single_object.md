- **系统痕迹语言（Med，取决于 UI 暴露面）**：rationale 中“允许来源”×10（内部白名单词汇）、“当前项目来源/当前项目研究事实”；review_advisories 中“系统未把重复提及升级为强制确认”是纯工程语言（出现在 §1/§3/§4/§9/§9.5/§14.2）；多条 evidence quote 含“当前正文=（当前为空，需生成实质正文）"。proposal 正文本身干净（"医学作者"0次、"允许来源"0次——好消息）。若这些字段会随候选渲染给用户，需在 UI 层过滤或改写为“现有项目资料”类中性表述。
- **跨项目语料提示执行不一致**：见上节 §12.1 条目（M5）。

设计目标：懒惰、视觉敏感、非技术型资深医学写作者——把点击压到真正分岔的医学决策，其余全部预选+转职能。

## Verdict And Residual Uncertainty

**结论**：v0.5 候选的**事实层质量高**——85/85 节覆盖完整（与模板目标集逐节一致），全部事实引用与 StudyDefinition r8 逐项一致，零数字级矛盾，零虚构参数/时限/法规条款，13 个缺口全部诚实阻断。**不可直接整体进入用户审阅**：阻断项不是医学事实错误，而是决定治理层缺陷——5 处正文预选（其中 §14.4 与 §8.4 构成正文间实体矛盾）、同一 fact_path 重复/冲突卡、73 张卡远超点击预算、系统性 fact_path 错绑。按 P0–P3 顺序修复后，23 个 complete 节与合并后约 10–14 张卡即可构成一次低负担的用户审阅。

**对隐含计划的最大异议（主动挑战）**：估计目标的术语混乱不在 artifact，而在**已确认的 StudyDefinition r8 本身**。当前修复计划的隐含假设是“事实源一致、正文复现即可”；此处不成立。安全的临时路径是保留正文忠实复现+§4.2.1 卡作为唯一升级点，同时必须向统计发起事实修订——若只在正文层“修顺”措辞而事实源不动，将制造合同所禁止的“正文与确认事实的静默漂移”。

**有界问题（供 Codex 同会话答复）**：
- **Q1（模板权限）**：模板无 §3.2（次要目的和次要终点）且无参考文献节（§12 直接跳 §14）。次要内容现由 §3 父节承载是否为模板本意？若否，需模板侧增节点而不是在 §3 里再塞正文——这影响再生范围。
- **Q2（产品行为）**：decision_required 章节的正文是否允许在用户确认前复述推荐选项？H1 的修复取决于答案：若是产品允许的行为，只需修 §14.4 一处实体矛盾；若不允许，需生成器批量中性化。
- **Q3（路由）**：MedDRA/EDC/e-consent/发表共享这类非医学写作者决策，确认走“默认推荐值+职能队列”而非用户点击？
- **Q4（工程）**：fact_path 是合同注册枚举还是自由字符串？若是枚举，`design.open_label_extension` 属生成器发明路径，是需修码的合同违规。

**残余不确定**：(1) 我未读 UI 渲染层，rationale/advisory/evidence quote 是否暴露给最终用户未知——“系统痕迹语言”严重度以此为条件；(2) 语料库（company_protocol_reference_corpus）的授权范围未验证，§8.2.3/§14.1 等借句是否合规超出本 packet 可判定范围；(3) 样本量复算基于正态近似，若统计采用了连续性校正或分层设计，132 例可能恰为正确值——此项按“待统计确认”而非缺陷记录。本报告为独立医学意见，非最终验收；Codex 保留全部裁定权。
