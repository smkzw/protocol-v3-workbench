# R03原子义务拆分示例（准备材料，非已接受registry）

本文件只细化已有源审阅的拆分，引用r03_candidate_node_crosswalk.json的原始定位/hash。未调用医学模型，未把示例当全量68源行覆盖或可执行QC。

| 来源 | 建议独立义务 | 适用和证据边界 |
|---|---|---|
| T3/R3 | 科学问题明确；目标人群；治疗条件；结局变量；伴发事件策略；人群汇总量；与终点/主要分析一致 | 五属性分别定位，不能以四个标题数量判断缺少属性；科学判断由内容审阅，结构存在不等于充分 |
| T4/R16 | CtQ识别；与风险相称控制；关键配制/给药；关键时间窗；个体暂停/终止；全试验暂停/终止；剂量调整 | 是否需要具体调整方案由研究事实决定，不复用其他药物数值；整试验停止不能全部绑到期中分析 |
| T5/R9 | 停干预继续随访；撤回同意；研究者终止参加；各情形的数据类型/时间/医学随访/既有数据处理/替换规则 | 以三情形逐项矩阵核对，不用一段“退出研究”统替；信息来源及退出后的允许范围必须明确 |
| T8/R6 | 委员会职责；工作程序；决策接口；AE随访周期和要求；妊娠等特定事件随访 | 委员会前三项按相应委员会存在性；后两项不能因无委员会一起被禁用 |
| T9/R3 | 总样本量；多中心预计分布；样本量假设/效力计算；临床依据 | 研究级样本量可复算；没有确定中心时不填假中心，中心分布的表达需按实际安排审阅 |
| T9/R7 | 制定SAP；锁库/揭盲前批准安排；偏离在CSR记录并解释 | 区分将来批准安排与已有批准证据；不伪造签署 |
| T10/R2 | 直接查阅覆盖研究者/机构/持源记录服务商；目的覆盖监查/稽查/监管检查/适用伦理审查 | 方案或引用协议可承载，外部协议未取得不自动标通过；不是本工作台软件安全工程 |
| T11/R2 | CtQ质量方法；相称监查策略；不依从识别；原因分析；CAPA；报告 | 对应实际项目安排和文件定位；不能只出现CAPA缩写就通过 |
| T13/R2 | 数据集合；来源；直接录入源数据；电子原始记录要求；系统适度验证/权限/轨迹/备份；必备记录保存/追溯；病历提取集合 | 作为试验方案内容义务保留；不能以用户排除软件安全专项为由删掉临床数据治理正文 |
| T14/R2、T15/R2 | 经费/保险；发表政策 | 如有独立协议，以已核实的引用承载；未知不能按“已在协议中处理”自动不适用 |

原子ID由源hash、XML定位、明确子项标识构成，不把6.x编号当唯一键。每条保留承载章节、证据/状态与未实现原因；human项复用必要确认，不生成逐行点选任务。首批只执行能客观核对的内容/版本/引用关系，医学充分性保留独立内容审阅。
